# AI 呼び出し制限（運用）

公開環境でも Anthropic 課金が膨らまないようにするためのガードと、コンソール側の確認手順。

## アプリ側（env）

| 変数 | 既定 | 意味 |
| --- | --- | --- |
| `AI_RATE_LIMIT_PER_MINUTE` | **オフ**（未設定または `0`） | ログイン利用者ごとのスライディング 60 秒あたりの許可回数。正の整数のときのみ有効。推奨を入れるなら `20` |
| `AI_CHAT_MESSAGE_MAX` | `4000` | AI チャット 1 メッセージの最大文字数（≥1 のとき上書き） |
| `AI_CHAT_HISTORY_TURNS` | `20` | モデルに渡す直近往復数（≥1 のとき上書き。`0` は未適用） |
| `AI_CHAT_MAX_OUTPUT_TOKENS` | `4096` | chat のみの maxTokens（≥1 のとき上書き）。refined／format の 8192 は別 |

- 値は TrimSpace。空・空白のみ＝未設定。不正値はその項目だけ既定を維持し、起動時に slog 警告（黙って別数に読み替えない）。
- **既定デプロイではレート制限は無効**。Anthropic 側で自動追加課金を ON にしていない前提で、機能だけ実装している。必要になったら `AI_RATE_LIMIT_PER_MINUTE` を設定する。
- Compose やシェルで意図せず export するとレートが有効になる。公開環境の env 一覧を定期的に確認する。
- 超過時は `POST .../ai-chat` と `POST /api/items/refined` が **429**、`code: ai_rate_limit`、固定文「AIの利用頻度が高すぎます。少し待って再試行してください。」。`ai_busy`／`ai_credit_limit` とは別 code。

既存の共有セマフォ（同時 4・`ai_busy`）とワークスペース・トークン上限（`ai_credit_limit`）はそのまま効く。

### プロジェクトのチャット

`POST /api/projects/{id}/ai-chat` は、1 メッセージの中でモデルを複数回呼ぶ（ツールで検索してから答える）ので、上の制限の効き方がアイテム単位のチャットと違う。値はコードの定数で、env では変えられない。

| 制限 | 値 | 意味 |
| --- | --- | --- |
| モデルの呼び出し | 1 メッセージで最大 **4 回** | `AI_CHAT_MAX_OUTPUT_TOKENS` は、その呼び出し **それぞれ** に掛かる（1 メッセージの出力は最大で 4 倍） |
| モデルとツールの時間 | 合わせて最大 **40 秒** | その間、共有セマフォ（同時 4）の枠を 1 リクエストが占め続ける |
| 同じユーザーの同時実行 | **1 件** | 実行中にもう 1 件送ると **429** `ai_busy` |
| ツールの結果 | 1 メッセージで合計 **40000 文字** まで | 超えた分は調べずに、ここまでの結果で答えさせる |
| リクエストの制限時間 | **50 秒** | この経路だけ（ほかは 15 秒）。超えると `code` の無い 503 |

- `AI_RATE_LIMIT_PER_MINUTE` は、ユーザーのメッセージ 1 件で 1 回分だけ数える（ツールやモデルの呼び出しの回数は数えない）。
- トークンは、1 メッセージの全呼び出しの **合計** がワークスペース・トークン上限（`ai_credit_limit`）に数えられる。
- クライアントが切断しても（パネルを閉じる、再読み込み）、実行は最後まで続く。その間（最大 40 秒）は、共有の枠と同じユーザーの実行中の印が残るので、直後に送り直すと **429** `ai_busy` になる。応答を受け取れなくても、利用量は数えられ、質問と回答は会話に足される（実行が終わってから開き直すと読める）。
- 長い実行が共有の枠を占めるので、プロジェクトのチャットが重なると、ほかの AI 機能（アイテム単位のチャット、refined／format）も `ai_busy` になりやすい。

### プロジェクトのチャットの履歴（会話）

履歴は「プロジェクト × ユーザー」ごとの会話に分かれて、データベースに残る（`project_ai_conversations` と `project_ai_messages`）。値はコードの定数で、env では変えられない。

| 上限 | 値 | 超えたとき |
| --- | --- | --- |
| 会話 | プロジェクト × ユーザーごとに **100 件** | 新しい会話を作った後で超えていたら、超えた分を、更新が古い順に全部消す（いま作ったもの以外。メッセージごと消える） |
| 1 つの会話のメッセージ | **200 件**（100 往復） | 保存のたびに、その会話の古い順に消す（ほかの会話は減らない） |
| 会話のタイトル | 最初のメッセージの先頭 **40 文字** | 超えたら末尾に「…」。名前は変えられない |
| 会話の一覧 | 最大 **100 件** | ページ送りは無い |

- モデルに渡すのは、続ける会話の直近 `AI_CHAT_HISTORY_TURNS` 往復だけ。ほかの会話の履歴は渡らない（会話を分けても、1 メッセージあたりの入力トークンは増えない）。
- 自分の会話でない ID への送信は **404** で、503・クレジット・回数制限・`ai_busy` より前に弾く。モデルは呼ばず、回数制限の 1 回分も使わない。
- モデルを待つ間に、続けていた会話が消されたとき（別のタブでの削除、上限の刈り込み）: 支払った回答は捨てずに、新しい会話として保存する。
- 起動時の初期化（`InitializeProjectAIChat`）は、`GET_LOCK('scrumboard_project_ai_conversations_migrate', 30)` の中で、テーブル・列・索引・外部キーを足し（既にあれば何もしない）、会話に属していないメッセージをプロジェクト × ユーザーごとに 1 つの会話にまとめ、メッセージの無い会話を消す。2 つのインスタンスが同時に起動しても、片方が待つ。30 秒待ってもロックが取れなければ、起動は失敗する（やり直せる）。引き継ぎと、メッセージの無い会話の掃除は、動いているインスタンスの保存と競合して MySQL がデッドロック（1213）かロック待ちの時間切れ（1205）を返したら、全部で 3 回までやり直す（保存のやり直しと同じ規則）。それでも競合が続けば、起動は失敗する（やり直せる）。保存している途中の会話は、掃除で消えない。
  - 引き継ぎでは 100 件の上限を刈り込まない。すでに 100 件ある組は一時的に 101 件になり、次に会話を作るときに 100 件に戻る。
- 入れ替えの途中・巻き戻し（古い版が新しいスキーマの上で動く）でも、書き込みは失敗しない。
  - 古い版が足したメッセージは、新しい版の次の起動まで、新しい版ではどの会話にも出ない（次の起動で 1 つの会話にまとまる）。
  - 古い版は、組の全体で 200 件に刈り込むので、会話をまたいで古いメッセージが消えることがある（合計が 198 件を超えている組だけ）。
  - 古い版の「履歴をクリア」はメッセージだけを消すので、新しい版の次の起動まで、タイトルだけの空の会話が一覧に出ることがある。
  - 新しい画面の送信（必ず `conversationId` か `newConversation` を付ける）が古い版に届くと、古い版は未知のフィールドとして **400**（「入力を確認してください。有効なJSONが必要です。」）を返す。回数制限とモデルより前なので、回数も費用も使わない。下書きは残るので、送り直せば、新しい版に届いた時点で通る。

### プロジェクトのチャットの提案（#150）

モデルは、提案のツール（`propose_status_change`・`propose_description_edit`・`propose_item_create`）で、アイテムの操作を提案できる。提案はアイテムを変えず、回答と一緒に `project_ai_proposals` に保存される。値はコードの定数で、env では変えられない。

| 上限 | 値 | 超えたとき |
| --- | --- | --- |
| 1 回の質問の提案 | **5 件**（受け付けたものだけ数える） | 6 件目からは「これ以上は提案できません。」をモデルに返す |
| 提案の説明・タイトル | アイテムと同じ（説明 10000 文字、タイトル 200 文字） | モデルに入力の誤りとして返す |

- 提案のツールは、上の「プロジェクトのチャット」の制限（モデル 4 回、ツールの結果 40000 文字、40 秒）の中で動く。ツールの結果は `{"proposed":true,"kind":…}` の短い固定文なので、結果の予算はほとんど使わない。
- 説明の編集は、置き換え後の **全文** をモデルが出力するので、出力トークンを使う。説明が長いと、1 回の呼び出しの `AI_CHAT_MAX_OUTPUT_TOKENS`（既定 4096）を超えて途中で切れ（`max_tokens`）、チャット全体が失敗する。そのとき回答も提案も保存されない（ほかの失敗と同じ）。
- 提案の状態の変更（`PATCH /api/projects/{id}/ai-proposals/{pid}`）と、適用（既存のアイテムの API）は AI を呼ばない。回数制限・トークン上限・`ai_busy` は掛からず、キーが未設定でも動く。
- 提案はメッセージに外部キー（`ON DELETE CASCADE`）で紐づくので、メッセージの刈り込み・会話の削除・全消去で一緒に消える。古い版のサーバー（このテーブルを知らない）がメッセージを消しても同じ。テーブルは起動時の初期化（`InitializeProjectAIChat` の同じロックの中）で作る。

## Anthropic コンソール（必須の運用確認）

アプリからコンソール API は呼ばない。運用者がコンソールで次を確認する。

1. [Anthropic Console](https://console.anthropic.com/) にログインする。
2. **Billing / Plans & Billing**（表記は UI により異なる）を開く。
3. **月額上限（spend limit / monthly limit）** が意図どおりか確認する。公開デモなら低めに置く。
4. **自動追加課金（auto reload / auto top-up）が OFF** であることを確認する。本リポジトリの公開環境はこの前提でレート制限を既定オフにしている。
5. 組織／ワークスペースが複数ある場合、本番キーが属する側の設定を見ていることを確認する。

キー漏洩や想定外の連打があっても、コンソール側の上限と自動チャージ OFF が最後の砦になる。
