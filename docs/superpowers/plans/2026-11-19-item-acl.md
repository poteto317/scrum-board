# アイテム閲覧／編集 ACL Implementation Plan

> **本フローではコミットしない**（`/feature`）。

**Goal:** アイテムごとに閲覧・編集 ACL を分離し、全公開（public 読取）と指定ユーザー制限を可能にする。

**Architecture:** `items.view_access` / `edit_access` / `created_by_user_id` ＋ `item_acl_entries`。認可ヘルパで view/edit/manage を判定。一覧は閲覧可のみ。public は当該 item 読取 GET のみセッション任意。

**Spec:** `docs/superpowers/specs/2026-11-19-item-acl-design.md`

**Tech Stack:** Go/MySQL、Angular/Vitest

## Global Constraints

- view: `public`|`open`|`restricted` / edit: `open`|`restricted`（public 禁止）
- edit ⇒ view。manage = admin ∪ 作成者。既存 created_by NULL は admin のみ manage
- 既存 migrate 既定: open/open。Create は常に open/open（作成ボディで ACL 不可）
- 一般 PATCH に `viewAccess`/`editAccess`/`viewUserIds`/`editUserIds`/`acl` → 400。ACL は `PATCH /api/items/{id}/acl` のみ
- manage 応答の `acl` は `{ viewUserIds: number[], editUserIds: number[] }`（配列単体ではない）。拒否は固定文（L-017）
- public 免除: `GET /api/items/{id}` と `GET /api/items/by-number/{n}` のみ。**`sessionExempt` パス一覧に items GET を足さない**。任意セッションで入ったあと行読取→`viewAccess=public` 判定（L-462）
- Create の `created_by_user_id` は **セッションユーザーのみ**。ボディの `createdByUserId` / ACL フィールドは無視または 400
- L-002 / L-017 / L-018 / L-037 / L-462 / L-463 / L-894（`AuthSession.ensureMe` の成功永続キャッシュ禁止を維持）
- `/feature` のためコミットしない
