# プロジェクト機能 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.  
> **Spec:** `docs/superpowers/specs/2026-11-17-projects-design.md`  
> **コミットしない**（`/feature`）。知見: L-001, L-037, L-040, L-455, L-456, L-459, L-460, L-472, L-841, L-842

**Goal:** プロジェクトでボード／バックログのアイテム表示と並び替え集合を仕切り、アクティブプロジェクトを settings に永続する。

**Architecture:** `projects` テーブル＋`items.project_id`。解決後アクティブは `board_settings.active_project_id`（JSON `activeProjectId`）。`GET /api/board`・`GET /api/backlog` と Reorder／Create の省略所属は解決後 id でスコープ。FE はヘッダーで CRUD／切替（busy→PATCH→再取得完了まで poll 抑止）、詳細で `projectId` 移動。

**Tech Stack:** Go / MySQL / Angular

## Global Constraints

- 列・番号・リストフィルタ・cardLayout／モバイル列はプロジェクト非依存。
- 並び替えは解決後アクティブの部分集合のみ（L-460）。フィルタ後配列を全件扱いしない（L-472・現行リストフィルタ踏襲）。
- settings 部分 PATCH は触ったキーだけ書く（L-841）。未知 `setting_key` 保持（L-459）。
- マイグレーションで既存 item の id／createdAt を振り直さない（L-456）。
- 深いリンク時のアクティブ自動切替は対象外。
- `/feature` 中はコミットしない。

### Task 1: Backend — projects ＋ items.project_id ＋ スコープ付き Board/Backlog/Reorder/Create

**Files:** 上記 projects／item 系

**Interfaces:**
```go
type Project struct {
  ID       int64     `json:"id"`
  Name     string    `json:"name"`
  Position int       `json:"position"`
  CreatedAt time.Time `json:"createdAt"`
  UpdatedAt time.Time `json:"updatedAt"`
}
// Repository 追加: ListProjects, CreateProject, UpdateProject, DeleteProject
// Item.ProjectID int64
// ItemInput.ProjectID *int64 `json:"projectId,omitempty"` — nil=省略→解決後アクティブ、非nilは検証
// ItemPatch.ProjectID *int64 — 変更時のみ
// resolveActiveProjectID(raw int64, projects []Project) int64
//   — raw が projects に存在すれば raw。無ければ position 昇順・同点は id 昇順の先頭。0件なら 0
// Board/Backlog: WHERE project_id = resolveActive…（アクティブ解決は Task2 の settings と併用。Task1 ではテスト用に project_id を直接指定できるリポヘルパ／一時的に設定行を書いてよい）
// ReorderItems: lock/検証対象を当該 project のカードに限定（列ごと完全集合はアクティブ内）
// ReorderBacklog: アクティブ全 ID 完全集合
// CreateItem: ProjectID nil → 解決後アクティブ。非nilは存在する id。next position/backlog は **同一 project 内** MAX+1
// UpdateItem projectId 変更: 移動先で position・backlogPosition を当該 project 末尾。移動元は欠番のまま
// DeleteProject: アイテム数>0 または projects 件数==1 → 専用 error → 409
// CreateProject name: trim 後 1〜80、空白のみ・空 → 400。削除後の再作成は新しい id（再利用しない・L-455）
```

- [x] **Step 1: 失敗するテスト**
  - Initialize: projects「メイン」1件、全 items にその id、再実行で id 不変（L-456）
  - CRUD: create／rename／list 順、空以外・最後1件 delete → 409、空かつ残≥2 → 204
  - 名前: 空／空白のみ／81文字超 → 400。trim して保存
  - L-455: delete 後に同名 create → 新しい id（旧 id 再利用なし）
  - Board/Backlog: 2プロジェクトにカードを分け、アクティブ settings（またはテストヘルパ）を切り替えたとき該当側だけ返る
  - Reorder: アクティブ部分集合で成功。他プロジェクト ID 混入や欠落 → mismatch。他プロジェクトの position 不変
  - Create 省略（nil）→ アクティブ所属。明示 projectId。不正 id → 400
  - PATCH projectId 移動: 先で末尾、元の他カード position 不変（欠番可）。**handler の decode body に `projectId` を含む**

- [x] **Step 2: RED** — `cd backend && go test ./internal/kanban/ -count=1 -run 'Project|Board|Backlog|Reorder|CreateItem'`

- [x] **Step 3: 実装** — migrate（main.go）→ repo → **handler.go**（projects ルート、`createItem`/`updateItem` の body に `projectId *int64`）→ `001_schema.sql` → **api.md に projects CRUD・item.projectId を追記**

- [x] **Step 4: GREEN** — 上記＋`go test ./internal/kanban/ -count=1`

**Done when:** プロジェクト CRUD と project スコープの Board/Backlog/Reorder/Create/移動がテスト緑。api.md に projects 節がある。

### Task 2: Backend — `activeProjectId` settings

**Files:** `board_settings.go`／migrate／handler／tests／api.md

**Interfaces:**
- `BoardSettings` に `ActiveProjectID int64 \`json:"activeProjectId"\``
- `BoardSettingsPatch` に `ActiveProjectID *int64`
- `applyBoardSettingsPatch(current BoardSettings, columns []Column, projects []Project, in BoardSettingsPatch) (BoardSettings, error)`
  - 3キーのいずれか必須。`activeProjectId` 指定時は `>0` かつ `projects` に存在、否则 `ErrBoardSettings`
  - `PatchBoardSettings` 内で projects を読んでから apply する
- `loadBoardSettings` 生値読取。Board GET 応答前に `resolveActiveProjectID` で解決して返す（DB 非更新）
- PATCH は触ったキーだけ UPSERT（L-841）。成功応答は解決済み3キー（＋既存）
- Initialize: projects が1件以上かつ行無ければ先頭プロジェクト id を冪等 INSERT

- [x] **Step 1: 失敗するテスト**
  - GET settings に activeProjectId（解決済み）
  - 無効 ID → 応答は先頭、DB 行は読取で不変
  - PATCH 有効 `{activeProjectId}` → DB 生値がその id に書き換わる（治癒）。再 GET で同値（リロード永続・受け入れ#3）
  - PATCH `{activeProjectId}` のみ → layout/mobile 不変・items 無し
  - PATCH layout のみ → active 生値不変（無効のまま残る・L-841）
  - 存在しない id／≤0 → 400
  - 未知トップレベルフィールド → 400
  - 未知 setting_key 行が GET／PATCH 後も DB に残る（L-459）
  - アクティブだった空プロジェクトを DELETE 後、GET board の解決済み activeProjectId は残存先頭（DB 生値は読取で直さない）

- [x] **Step 2–4:** RED → 実装 → **api.md の board settings に activeProjectId を追記** → GREEN（`go test ./internal/kanban/ -count=1`）

**Done when:** activeProjectId の読取解決・部分 PATCH・シード・治癒・削除後フォールバックが緑。Board フィルタがこの解決値を使う。

### Task 3: Frontend — 型・API・ヘッダー CRUD／切替・board/backlog 再取得

**Files:** models／api／app.*／board.ts／backlog.ts／project-session（新規）／specs

**Interfaces:**
```ts
export interface Project { id: number; name: string; position: number; /* timestamps optional */ }
// BoardSettings.activeProjectId?: number
// Item.projectId: number（normalize 後）
// Api: listProjects / createProject / patchProject / deleteProject
// patchBoardSettings に activeProjectId?: number 追加
```

- [x] **Step 1: 失敗するテスト**
  - normalize: projectId／activeProjectId 補完、未知 settings キー保持
  - ヘッダー切替: **busy を楽観より先**（L-842）。PATCH→**再取得完了まで** busy／poll 無効（board・backlog、L-040）
  - 切替 PATCH 失敗: セレクトを前の id に戻し、エラー、busy 解除（成功扱いしない）
  - 再 load 後も activeProjectId が同じ（受け入れ#3 の FE 側）
  - CRUD 失敗で一覧を確定しない（L-001）
  - 削除ボタン: アイテム0かつ残≥2 のときだけ（または DELETE 409 を表示）
  - 新規カード作成: 省略または明示 `projectId` でアクティブに入る（ボード／バックログ経路）
  - リストフィルタ ON 時の DnD／キーボード並べ替え: 現行制約を破らない回帰（L-460/L-472・受け入れ#5）
  - 切替後: 件数表示・リストフィルタ・モバイル1列がアクティブ部分集合で動く回帰観点（受け入れ#6。モバイルは既存 board-mobile テストとの組み合わせで可）

- [x] **Step 2: RED** — 該当 `ng test`／vitest

- [x] **Step 3: 実装**
  - `ProjectSession`（providedIn root）: projects signal、activeId、**`switching`（唯一の切替 busy 名。`settingsSaving` とは別）**、load/create/rename/delete/switch
  - `app.html`: select＋追加／改名／削除（確認）。workspace 表示をプロジェクト UI に置換
  - board／backlog:
    - `ProjectSession.switching()` 中は live refresh apply しない
    - 切替成功後に自前 load（**再取得完了まで `switching` 維持**）
    - **`canReorderItems` / `canReorder` にも `!switching()` を含める**（切替中 DnD 禁止。L-460）
  - 新規カード作成経路が active を送る／省略（サーバ解決）どちらでも仕様どおり

- [x] **Step 4: GREEN**

**Done when:** ヘッダーでプロジェクト切替・CRUDでき、board/backlog がアクティブだけを示し poll 巻き戻しなし。フィルタ／件数／モバイル回帰あり。
