# スプリント機能 Implementation Plan

> **For agentic workers:** 本リポジトリの `/feature` ではコミットしない。実装後の commit は後続の `/commit-ja` に任せる。Steps は checkbox で進捗管理する。

**Goal:** プロジェクト単位でスプリントの期間・ゴール・メンバー・ベロシティ（手動）を管理できるようにする（ITEM-082）。

**Architecture:** 新規 `sprints` / `sprint_items` を起動時 migrate。Go handler → Repository（TX）で CRUD・activate・complete・メンバー置換。アイテム soft delete / `projectId` 変更で接合行を掃除。Angular は `/sprints`・`/sprints/:id` とサイドバー導線。ボード／バックログは触らない。

**Tech Stack:** Go 1.22+ `ServeMux`、MySQL、Angular standalone + Vitest、既存 session auth / ACL。

**Spec:** `docs/superpowers/specs/2026-11-21-sprint-design.md`

**知見チェック（優先度 A 関連）:** L-001, L-002, L-038, L-044, L-046, L-047, L-062, L-456, L-460, L-542, L-791, L-858, L-901, L-930, L-934

## Global Constraints

- クエリ／所属は `projectId`（L-934）。省略時は解決後アクティブ。
- 状態遷移: `planned`→`active`（activate のみ）、`active`→`completed`（complete のみ）。PATCH で status 変更しない。planned から直接 complete は 409。
- プロジェクトあたり active は最大 1（activate は競合チェック込み 1 TX）。
- `suggestedVelocity` = メンバーのうち列名が正確に `"Done"` の件数。`Close` 除外。Done 列なしは 0。
- `velocity` は completed のみ。未完了でキーがあれば 400。省略≠`null`（L-002）。
- メンバー PUT: クライアントは可視・edit 可の完全集合。サーバは view 不可の既存メンバーを維持（L-460 / L-901）。`itemCount` も CanView 基準。
- soft delete / `projectId` 変更: 当該 `item_id` の `sprint_items` をすべて削除。
- プロジェクト削除: 生存アイテム 0 かつスプリント 0。
- 日付は `YYYY-MM-DD` のみ。`startDate > endDate` や無効暦は 400（L-044）。
- goal 上限 2000 Unicode スカラー（FE/BE 同値。L-858）。name trim 後 1〜120。
- ハンドラ: 入力検証 → 権限 → DB（L-930）。PUT items / activate / complete は各 1 TX（L-038）。
- UI: 保存成功まで確定しない（L-001）。activate/complete 中は disabled、成功後再 GET（L-062）。詳細 dirty は `canLeave`（L-542: root サービスに下書きを置かない）。
- ボード／バックログ／ストーリーポイントは対象外。コミットしない。

**Interfaces（Go）:**

```go
type SprintStatus string // planned | active | completed

type Sprint struct {
  ID, ProjectID int64
  Name, Goal string
  StartDate, EndDate string // YYYY-MM-DD
  Status SprintStatus
  Velocity *int
  SuggestedVelocity int
  ItemCount int
  Items []SprintItem // detail only; order = position asc
  CreatedAt, UpdatedAt time.Time
}

type SprintItem struct {
  ID, Number, ColumnID int64
  Title string
}

type SprintCreateInput struct { Name, Goal, StartDate, EndDate string; ProjectID *int64 }
// Velocity 三態は ItemPatch.dueAt と同型: デコードで RawMessage → Velocity *int + ClearVelocity bool（**int は使わない。L-002）
type SprintPatch struct {
  Name, Goal, StartDate, EndDate *string
  Velocity *int
  ClearVelocity bool
}
```

Repository（追加）:
- `ListSprints(ctx, projectID) ([]Sprint, error)` — summary。ItemCount は handler で CanView 再計算してよい
- `GetSprint(ctx, id) (Sprint, error)` — items は `position` 昇順
- `CreateSprint(ctx, SprintCreateInput) (Sprint, error)`
- `UpdateSprint(ctx, id, SprintPatch) (Sprint, error)`
- `DeleteSprint(ctx, id) error` — completed → conflict
- `ReplaceSprintItems(ctx, id, itemIDs []int64, retainIDs []int64) (Sprint, error)` — 1 TX。最終順序 = **可視 `itemIDs` の順（position 0..）の直後に、不可視 `retainIDs` を置換前の相対順のまま付与**（密）。この規則でテスト固定
- `ActivateSprint(ctx, id) (Sprint, error)` — 1 TX
- `CompleteSprint(ctx, id, velocity *int) (Sprint, error)` — 1 TX
- `CountSprintsForProject(ctx, projectID) (int64, error)`
- `DeleteSprintItemsForItem(ctx, itemID) error`

Migrate / schema: `sprint_items.position INT NOT NULL`（0 始まり・密）。

  - 作成成功・`name` 空白のみ 400・`goal` 2001 スカラー 400
  - 一覧 `start_date` 降順・同日 `id` 降順。**一覧各行 `itemCount` が view 不可を含まない（L-901）**
  - GET／PATCH（期間・ゴール）／DELETE（planned OK、completed 409）

**Interfaces（TS）:**

```ts
export type SprintStatus = 'planned' | 'active' | 'completed';
export interface SprintSummary {
  id: number; projectId: number; name: string; goal: string;
  startDate: string; endDate: string; status: SprintStatus;
  velocity: number | null; itemCount: number;
  createdAt: string; updatedAt: string;
}
export interface Sprint extends SprintSummary {
  suggestedVelocity: number;
  items: { id: number; number: number; title: string; columnId: number }[];
}
export interface SprintPatch {
  name?: string;
  goal?: string;
  startDate?: string;
  endDate?: string;
  velocity?: number | null; // null = クリア（L-002）。省略 = 変更なし
}
```
