# Board / backlog ETag・304 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET /api/board` と `GET /api/backlog` が ACL フィルタ後ボディの ETag と条件付き GET（304）を返し、ボード／バックログの 5 秒ポーリングは 304 のとき解析・`sameJson`・キャッシュ更新を走らせない。

**Architecture:** サーバは `json.Marshal` → SHA-256 → 強い ETag。`If-None-Match` 一致で 304（本文なし・Content-Type なし・ETag あり）。クライアントはポーリングだけ条件付き GET し、Angular の 304 エラーを `notModified` に写す。バックログの `forkJoin` は両方 304 なら emit なし、片側 200 なら既存 state とマージ。

**Tech Stack:** Go (`net/http`, `crypto/sha256`)、Angular `HttpClient` + RxJS、既存 `live-refresh` / `HttpTestingController`、`docs/openapi.yaml`。

**Spec:** `docs/superpowers/specs/2026-11-23-board-etag-304-design.md`

**知見:** L-775, L-001。ETag は post-ACL。

### Task 1: サーバ ETag ヘルパと board/backlog

**Files:**
- Modify: `backend/internal/kanban/http_transport.go`
- Modify: `backend/internal/kanban/handler.go`
- Create: `backend/internal/kanban/etag_reply_test.go`（名前は既存慣習に合わせ可）

- [ ] **Step 1: 失敗するテストを書く**

  - HTTP ハンドラ経由で同一ボードを二度 GET: 1 回目の ETag を `If-None-Match` に付けて 304・本文空・`Content-Type` 無し・`ETag` あり。グローバル `no-store` が 304 でも付くこと（ハンドラ外側ミドルウェア経由ならその経路で検証）。
  - `If-None-Match` **欠如** → 200 + 本文 + ETag。
  - 不一致タグ → 200・JSON 本文・計算どおりの ETag。
  - アイテム更新（または同等のボディ変更）のあと → 200・**別 ETag**。
  - `If-None-Match: *` → 304。カンマ区切りで 2 つ目が一致 → 304。
  - クライアントが送る **弱 ETag** `W/"<hex>"` がサーバ強いタグと一致 → 304。
  - 可能なら最小 ACL fixture: フィルタで見える集合が違うユーザーが、他ユーザーの ETag を付けても **誤 304 にならない**（fixture が重い場合はヘルパに「異なる body → 異なる etag」単体 + ハンドラで filter 後 body を渡すことをコメントで固定し、統合は 1 本）。


### Task 5: Backlog forkJoin 合成

**Files:**
- Modify: `frontend/src/app/backlog.ts`
- Modify: backlog spec

- [ ] **Step 1: 失敗するテスト**

  - 両方 304 → apply なし。
  - board だけ 200 → backlog は直前 state、board は新 body で apply。
  - backlog だけ 200 → 対称。
  - 両方 200 → 両方新 body。
  - プロジェクト切替で ETag キー破棄。

- [ ] **Step 2: 実装**

  - **backlog 画面の `fetchKey` は常に `0`**（現行どおり `api.backlog()` / `api.board()` に projectId クエリ無し）。board 画面だけ `boardProjectIdForFetch() ?? 0`。
  - Api の conditional は **常に union を 1 回 emit**（`notModified` も含む）。`forkJoin` で両脚を待ち、合成後に **両方 `notModified` なら `EMPTY`**（`startLiveRefresh` の `apply` を呼ばない）。片側/両側 `ok` ならマージ結果を 1 回 emit。
  - 初回 `load` / `reloadAfterProjectSwitch` は無条件 GET で ETag を保存。切替時は `(board|backlog, 0)` を破棄してから取り直す。
  - 設計書の合成規則。ETag キーは `(board|backlog, fetchKey)`。

- [ ] **Step 3: GREEN**

```bash
cd frontend && npm test -- --no-watch --browsers=ChromeHeadless --include='**/backlog*.spec.ts'
```
