# プロジェクト URL でボードを開く（#86）— 設計

- カード: [#86 URLで直接プロジェクトを開けるようにする](https://scrum-board-jkcejsb6ka-an.a.run.app/items/86?project=1)
- 日付: 2026-11-22

## 背景

- アイテム詳細は既に `/items/{n}?project={id}` でプロジェクトを特定できる。
- かんばんボード（`/`）はサーバの `activeProjectId` とヘッダ切替だけに依存し、**プロジェクトを指す共有可能な URL が無い**。
- API のボード GET は既に `?projectId=` を受け取る（FE `api.board(projectId)`）。不足は主に FE のディープリンク。

## 決めたこと

| 項目 | 決定 |
| --- | --- |
| URL 形 | **クエリ** `/?project=<正の整数>`（アイテムと同じクエリ名 `project`）。パス `/projects/:id` は本カードでは採用しない |
| 対象画面（inbound） | **ボードルート `/` のみ**で URL 起点の `switchTo` を行う。`/backlog`・`/items/:n` 等では inbound 適用しない（詳細の既存 `?project=` と衝突しない） |
| 切替手段 | 既存 `ProjectSession.switchTo`（settings PATCH で永続化）。セッションだけの仮切替はしない |
| 適用タイミング | `projectSession.load()` **成功直後・1 回だけ**、現在がボードルートかつ URL に `project` があるとき。popstate／クライアント遷移後の再適用はしない |
| ログイン redirect | 既存のログイン後戻り先がクエリを保持している前提。login フロー改修は本カード外 |
| クエリ解析 | `ActivatedRoute`／`UrlTree` から `project` を取る。値が **1 件**かつ trim 後 `/^\d+$/` で、`Number` が有限の正の整数（≥1）のみ **有効**。欠落のみ → 何もしない（エラー無し）。値ありだが不正（非数字・`01`・`+1`・`1.0`・≤0・空文字）または **同一キー複数** → 切替せず、固定文言エラー（L-044: 黙って既定ボードへ流さない） |
| 未知 id | 一覧に無い有効整数。存在確認 API は呼ばない。切替せず、固定文言エラー |
| 固定文言（未知／不正クエリ） | `指定のプロジェクトが見つかりません。` |
| switchTo／PATCH 失敗 | 既存の失敗表示をそのまま使う。上記固定文言に置き換えない（L-001） |
| outbound URL 同期 | ヘッダ切替・作成後切替とも **`switchTo` 成功後のみ**、現在 URL に `project` を replaceUrl + merge で付与（履歴を汚さない）。失敗時は URL を変えない。共有 URL を切替後も使えるようにするための最小付帯（inbound だけでは往復できない） |
| BE | **変更なし** |
| docs | **`README.md` に「ボード共有 URL」1 節**。OpenAPI 必須変更なし |
| コピー UI | 作らない |
| 配置 | ロジックは `App`。解析は純関数 |
| AC 検証 | 自動テスト必須 |
| poll（L-860） | URL 適用成功後、poll／settings 再取得が別プロジェクトへ黙って戻さない（既存世代／busy を壊さない） |
| 遅延完了（L-037/L-040） | URL 起点も既存 `switchTo` の世代／busy に乗る。適用開始後に別切替が勝った場合、遅延成功で active／URL を上書きしない（新世代機構は作らない） |

## 非目標

- `/projects/:id` パスルーティング
- 未ログイン公開ボード
- プロジェクト名スラッグ URL
- BE 新規エンドポイント
- ボード専用コピーボタン／QR
- ログイン redirect の改修
- popstate でのプロジェクト再切替
- `/backlog` 等への inbound ディープリンク（別カード）

## 利用者体験

1. `https://…/?project=2` を開く（ログイン済み）→ プロジェクト 2 のボードが表示される。
2. ヘッダで別プロジェクトへ切替成功 → アドレスバーの `project` が更新される。
3. `project=999` または `project=abc` → アクティブは変わらず、ヘッダ error 面に「指定のプロジェクトが見つかりません。」。
4. クエリ欠落 → エラー無し。サーバ解決のアクティブのまま。

## 実装概要（FE）

- クエリ解析の純粋関数（上記規則）。
- `App`: load 成功後、ボードルートなら 1 回適用。
- ヘッダ／作成後: `switchTo` 成功時のみ URL 同期。
- テスト: 解析境界、有効 id で switchTo、不正／未知で switchTo 無し＋文言、非ボードでスキップ、切替成功で URL、失敗で URL 不変、適用後 poll が戻さない（既存ガード前提の回帰）。

## 受け入れ条件（#86）

1. ログイン済みで `/?project=<一覧にある id>` を開くと、そのプロジェクトのボード内容になる（自動テスト）。
2. 不正な `project`（値あり）または重複キーでは switchTo せず、固定文言を出す（自動テスト）。
3. クエリ欠落ではエラーも switchTo も無い（自動テスト）。
4. 未知 id では switchTo せず、固定文言を出す（自動テスト）。
5. ヘッダ／作成後の `switchTo` **成功後**、URL の `project` が新しい id になる。失敗時は URL 不変（自動テスト）。
6. URL 適用成功後、poll／settings 再取得がアクティブを別プロジェクトへ戻さない（自動テストまたは既存ガードの回帰）。
7. BE 契約は変えない。
