# 説明欄の URL をタイトル付きブックマークカードで表示する（#157）設計

## 背景

カード #157: 「Notion のブックマークのように、説明欄に貼った URL をタイトル付きで表示できるようにする。タイトルの取得はサーバー側になるため、取得先の制限（SSRF 対策）とキャッシュを設計で決める。」

#145 で画像・リンクの貼り付けと複数画像に対応済み。リンクは `[label](https://…)` として保存され、表示はインラインの `<a>`。外部ページのタイトル取得・カード UI・任意 URL 向けの SSRF ガードは無い。既存の外向き HTTP は GitHub PR タイトル（ホスト固定）のみ。

## 決めたこと

### 範囲

- **対象本文:** 説明とソリューション。カード文面は「説明欄」だが、両者は同一のブロック／リッチテキスト経路を共有するため一体で直す（片方だけカード化すると表示が食い違う）。コメントは対象外（別カードで足せる）。
- **対象リンク:** 「ブックマーク候補」だけをカード表示する。候補の定義は次のとおり。
  1. Markdown リンク `[label](url)` について、パース直後の生文字列で **`label === url`** であり、かつ `normalizeDescriptionLinkUrl(url) !== null`（フロント）／サーバー側の同規則で合法であること。label 側を別途「正規化してから比較」しない（比較式はこれ 1 つ）。
  2. 1 つの段落ブロック全体が、上記のリンク 1 件だけ（前後の空白・改行のみ可）。リスト項目・見出し内のインラインリンクはカードにしない（インライン `<a>` のまま）。
- **名前付きリンク**（`[GitHub](https://…)` など `label !== url`）は、これまでどおりインラインリンク。意図的な表示名を壊さない。
- **添付パス**（`/api/items/.../attachments/.../content`）は候補にしない（既存の image / file セグメント）。
- **新規記法は作らない。** 本文の保存形式は既存の `[url](url)` のまま。
- **パース:** `parseDescriptionLinks`（およびブロック組み立て）の結果として `kind: 'bookmark'` セグメントを出す。表示コンポーネントは `bookmark` をカード描画し、表示時に「段落がリンク1件か」を再判定しない。共通の判定は `isBookmarkLink(label, url)`（名前はこのまま）に置き、エディタのリッチプレビューとアイテム閲覧の両方が同じパース経路を使う。
- **貼り付け:** 追加の自動変換はしない（#145 のまま）。単独 URL を貼って `[url](url)` になる／手で書いた場合が候補になる。
- **UI の境界:** 既存アイテムの説明・ソリューションの編集プレビューと閲覧表示のみ。新規作成フォームの説明欄は対象外（範囲外）。

### サーバー API

- **`POST /api/link-previews`**（ログイン必須。Cookie / Basic）。
- リクエスト: `{ "urls": string[] }`。最大 **20** 件／リクエスト。各 URL は既存の説明リンクと同じ規則（`https:` のみ、長さ ≤ 2048、制御文字・`()` 禁止）で正規化する。不正・重複は落とし、正規化後の集合だけ処理する。
- レスポンス: `{ "previews": { "<url>": Preview } }`。`Preview` は次のいずれか。
  - `{ "ok": true, "title": string }` … `title` は非空（抽出後に空なら失敗扱いで下へ）。
  - `{ "ok": false }` … `title` キーは付けない。拒否・タイムアウト・非 HTML・パース失敗など。クライアントはホスト名フォールバックを使う。
  - キーは正規化後 URL。リクエストに含まれ正規化に成功した URL は、成功・失敗を問わず必ず 1 エントリ返す。正規化失敗・重複除去で落ちた URL はキーを作らない。
- **認可:** ログイン済みなら可（本文に書いた公開 URL のプレビュー）。PR タイトル API と違い GitHub トークンは使わない（L-1034 のトークン消費問題は対象外だが、同様に「特権付きクライアントで任意 URL」は禁止する設計とする）。
- OpenAPI（`docs/openapi.yaml`）を実装と同時に更新する。

### SSRF 対策（必須）

外向き GET は次をすべて満たす専用クライアントだけが行う（`http.DefaultClient` や共有 PR 用クライアントは使わない）。

1. **スキーム:** `https` のみ。`http`・その他は拒否（L-1058 とも整合）。
2. **ユーザー情報:** URL に userinfo（`user:pass@`）があれば拒否。
3. **ホスト:**
   - ホスト名が空、または IP リテラルの場合は、その IP が「公開ユニキャスト」でなければ拒否。
   - ホスト名の場合は解決した **すべての** A/AAAA が公開ユニキャストであること。1 つでも非公開なら拒否。
   - 拒否するアドレス種: ループバック、RFC1918、リンクローカル、CGNAT（100.64.0.0/10）、マルチキャスト、未指定、IPv6 ULA / リンクローカル。
   - **拒否ホスト名（閉集合。追加は別変更）:** `localhost`、`metadata.google.internal`、`metadata`、`kubernetes.default`、`kubernetes.default.svc`。大文字小文字は折りたたんで比較する。
4. **接続:** カスタム `DialContext` で、実際に繋ぐ IP を再度同じ公開 IP 判定に通す（DNS rebinding 対策。L-1150 の趣旨）。
5. **リダイレクト:** 最大 **3** 回。各 Location 先 URL に対し、上記 1〜4 をやり直す。失敗したらその URL は `ok: false`（L-1099 の「リダイレクトすり抜け」を意識）。
6. **タイムアウト:** 接続＋応答ヘッダ＋本文読み取り全体で **3 秒**（クライアント `Timeout`）。本文は最大 **512 KiB** で打ち切り（L-052 / L-054）。
7. **応答:** `Content-Type` が `text/html`（または `+html`）を含まない場合はタイトル取得せず `ok: false`。ステータスが 2xx 以外も同様。
8. **並行:** プロセス全体で同時外向きは最大 **8**。同一 URL の同時要求は 1 フライトにまとめる（`PRTitleResolver` と同型）。
9. **認証非付与（必須）:** リンクプレビュー専用クライアントには Cookie / Basic / `Authorization` / GitHub トークンなどアプリの資格情報を一切載せない。他用途（PR タイトル等）の `http.Client` と Transport を共有しない（L-1058 / L-1034）。
10. **ログ:** 失敗理由に秘密や応答本文全文を出さない（L-017）。

### タイトル抽出とキャッシュ

- HTML から次の順で最初の非空を採用: `og:title` → `twitter:title` → `<title>`。
- HTML 実体をデコードし、空白を畳み、Unicode 長 **200** で切る（L-836）。切った結果が空なら `ok: false`。
- **キャッシュ:** プロセス内 map（Redis なし。既存方針）。成功 TTL **10 分**、失敗 TTL **1 分**、上限 **512** エントリ（古いものから捨てる）。
  - **必須（PR タイトルと同型）:** 期限切れでも直近の成功エントリがあれば即返し、背景で再取得する（stale-while-revalidate）。背景再取得が失敗しても、成功エントリの保持期限（成功確定から最大 **1 時間**）内は成功タイトルを返し続け、失敗キャッシュで上書きしない（stale-if-error）。
  - 一度も成功していない URL の初回だけ呼び出し側が取得完了を待つ（上限は API 全体の 3 秒タイムアウト内）。
- 永続テーブルは作らない（再起動で消えてよい。負荷は SSRF ガードとバッチ上限で抑える）。

### フロント表示

- カード UI（既存アイテムの説明・ソリューションの編集プレビューと閲覧）:
  - タイトル（取得前はホスト名、取得後は title。失敗時もホスト名のままインライン化せずカード枠は維持し、タイトル行にホスト、副行に URL 短縮表示）。
  - カード全体をクリック可能にし、`target=_blank` `rel=noopener noreferrer` で開く。
  - 取得中は「読み込み中」の短文をタイトル行に出す。
- **世代破棄（L-037 / L-040）:** プレビュー要求を始めるときに世代トークン（アイテム番号＋本文の世代カウンタ、または同等）を控え、応答適用前に一致を確かめる。アイテム切替・本文の再パース・後続バッチのどれで不一致でも破棄する（切替だけではない）。
- バッチ: 表示中の `bookmark` から URL を集め、送信前に必ず `normalizeDescriptionLinkUrl` し、**その戻り値だけ**をリクエスト配列と `previews` のキー参照に使う（L-018）。最大 20 件ずつ。HTTP 失敗や欠落キーはホスト名フォールバック（L-001: 成否を見てフォールバック。黙って空にしない）。
- `showRichPreview` は bookmark を含むときに true（#156 の file と同様）。

### 既存コードとの関係

- 外向き取得の実装は `PRTitleResolver` をコピーせず、**リンクプレビュー専用**のパッケージ／ファイルに置く（GitHub トークン経路と混ぜない）。キャッシュ・inflight・スロットの型は似せてよい。
- URL 正規化はフロントの `normalizeDescriptionLinkUrl` と同趣旨の規則をサーバーでも実装し、テストで両方の拒否例を揃える（L-018）。

## 受け入れ条件

1. 説明（およびソリューション）で、段落全体が `[https://example.com/x](https://example.com/x)` のとき、閲覧・プレビューでタイトル付きカードになる。
2. `[表示名](https://example.com/x)`（label ≠ url）はインラインリンクのまま。
3. リストや見出しの中の同型リンクはインラインのまま（カード化しない）。
4. タイトルはサーバーが HTML メタから取り、クライアントは任意オリジンへ直接 fetch しない。
5. プライベート IP・ループバック・メタデータホスト・`http:`・userinfo 付きはプレビューせず、カードはホスト名フォールバック（または同等の安全な表示）で、サーバー内部へは届かない。
6. リダイレクト先が非公開なら拒否する。
7. タイムアウト・非 HTML・巨大応答でも UI は固らず、他の本文は見える。
8. アイテム切替・同一アイテムの本文変更・並走バッチのいずれでも、古いプレビュー応答で表示が上書きされない。
9. コメント欄の同型リンクは従来どおりインライン（変更しない）。
10. OpenAPI に `POST /api/link-previews` が載る。
11. リンクプレビューの外向き要求にアプリ認証ヘッダが付かない。

## 範囲外

- ファビコン・OGP 画像・説明文（description）の表示。
- コメント・新規作成フォーム。
- 本文への新記法や「ブックマークブロック」ボタン。
- Redis / DB 永続キャッシュ。
- ブラウザからの直接 OG 取得。
- PDF 等の非 HTML プレビュー。
- #158（画像拡大）やその他 Notion 項目。

## 気をつける知見

- **L-001** プレビュー API・クライアント呼び出しの成否を見てフォールバックする。
- **L-018** 正規化・候補判定・href が同じ値の経路を通る。
- **L-037 / L-040** アイテム切替・世代で古いプレビューを捨てる。
- **L-052 / L-054** タイムアウトが本文読み取りまで含む。サイズ上限。
- **L-017** エラーログに本文・秘密を出さない。
- **L-1034** 特権トークン付きクライアントで任意 URL を取らない（本 API はトークン無し・SSRF ガード必須）。
- **L-1099 / L-1150** リダイレクトと DNS rebinding（接続時 IP 再検査）。
- **L-836** タイトル長・URL 長の上限。
- **L-1058** 平文 http へ資格情報を送らない（https のみ・userinfo 拒否）。
