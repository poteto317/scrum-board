# AI チャット（MVP）— 設計

- カード: [#24 AIチャット機能を搭載する](https://scrum-board-jkcejsb6ka-an.a.run.app/items/24?project=1)
- 日付: 2026-11-21

## 背景

- Notion AI 風のアシスタント、クレジット API 連携、設定での残量表示が求められている。
- 現状の AI は `POST /api/items/refined`（カード整形起票）のみ。チャット UI・利用量表示は無い。
- フル機能は 1 プランに収まらないため、**今回は MVP** に限定し、ボード横断アシスタントやツール実行は後続とする。

## 決めたこと（推奨案を採用）

| 項目 | 決定 |
| --- | --- |
| スコープ | **MVP**: アイテム詳細の AI チャット＋設定の利用状況表示。エージェント自動操作・ボード横断チャットは対象外 |
| 置き場 | アイテム詳細内のパネル（そのアイテム文脈） |
| 能力 | title／description／comments（閲覧可範囲）を文脈に Q&A・要約・文案提案。**適用先は description と comments のみ**（title は文脈専用）。書き込みはチャット API の外 |
| 適用の責務 | **チャット API は本文を変更しない。** FE が確認 UI のあと既存 `PATCH /api/items/{id}`（description）／`POST .../comments` だけを呼ぶ |
| パネル表示 | **セッションありかつ `canEdit` のときのみ** AI パネルを出す。閲覧のみ・未ログイン public では非表示（履歴の覗き見もしない） |
| クレジット | 既存 `ANTHROPIC_API_KEY` を使用。**アプリ側でトークン／回数を集計**して表示。Anthropic Admin／Usage API は使わない |
| 利用状況の閲覧 | `GET /api/ai/usage` は **ログイン済みなら誰でも可**（ワークスペース全体の累計。admin 限定は後続可） |
| 設定 UI | 新ルート `/settings`（ヘッダー等から到達）。AI 利用状況＋キー未設定時の案内 |
| 永続化 | **アイテム単位でサーバ保存**（再訪で履歴が残る） |
| プロバイダ | Claude のみ（既存 `aiformat`／SDK と同系統）。マルチプロバイダは対象外 |
| 同時実行 | refined と **同一セマフォを共有**（合計同時実行の上限。超過は 429） |

## 非目標（今回やらない）

- ボード全体の Notion 風アシスタント、ステータス変更・起票などのツール呼び出し
- Anthropic 組織の課金残額・クレジット残高の外部 API 取得
- ストリーミング UI の必須化（初期は非ストリームでよい。後から追加可）
- コメント欄への AI 発言の混在保存（チャットは専用ストア）
- キーの UI からの保存（キーは従来どおりサーバ環境変数）

## 利用者体験

1. 編集可能なアイテム詳細でのみ「AI」パネルを表示する（上記「パネル表示」）。
2. メッセージを送り、当該アイテムの文脈付きで応答を得る。履歴は同じアイテムに紐づく。
3. 応答から「説明に反映」「コメントとして追加」を選んだとき、確認のあと FE が既存 PATCH／comments API を呼ぶ（チャット API・サーバは description／comments を書き換えない）。
4. `/settings` で累計リクエスト数・入出力トークン概算（サーバが Anthropic 応答から記録したもの）と、AI 未設定時の案内を見る。

## API（案）

正本は実装時に `docs/openapi.yaml` へ載せる（update-api-doc スキル）。概要のみ。

| Method | Path | 内容 |
| --- | --- | --- |
| GET | `/api/items/by-number/{n}/ai-chat` | 履歴（古い順）。**セッション＋編集可**（パネルと同じ）。キー未設定でも履歴は返す |
| POST | `/api/items/by-number/{n}/ai-chat` | `{ "message": string }` → ユーザー＋アシスタント発言を追記し応答。セッション＋編集可。**AI 未設定は 503**（キー有無はこの POST でのみ必須） |
| DELETE | `/api/items/by-number/{n}/ai-chat` | 履歴クリア。セッション＋編集可。キー未設定でも可 |
| GET | `/api/ai/usage` | 集計（リクエスト数・input/output tokens 等）＋キー設定有無フラグ。**ログイン済みなら可** |

- メッセージ長・履歴コンテキスト長に上限を設ける（数値は実装プランで固定）。
- 同時実行は refined と **同一セマフォ**。超過は 429。
- 失敗は既存 refined に倣い、上流文言をクライアントへ漏らさない（固定 `message`／必要なら `code`）。
- `security`: Cookie セッション必須。ACL は item の **edit**（usage はログインのみ）。

## データ

- 新テーブル例: `item_ai_messages`（`item_id`, `role` user|assistant, `body`, `created_at`, 任意で `input_tokens`/`output_tokens`）
- 利用集計: グローバルまたはユーザ単位の累計テーブル／行（MVP は **ワークスペース全体の累計** で足りる。ユーザ別は後続可）。Anthropic の usage フィールドが取れる範囲で加算。取れない場合は回数のみ。
- アイテム削除時は履歴 CASCADE または明示削除（ゴミ箱方針に合わせ実装プランで固定）。

## FE

- `ItemDetail` に AI パネル（既存コメントと並立。コメントコンポーネントは改変最小）。
- `/settings` ページ: 利用状況表示、未設定時の説明（キーはサーバ env）。ヘッダーメニューからリンク（catalog に追加する場合は既存 header-menu の許可 ID 規則に従う）。
- 適用操作は既存 API（item PATCH、comments POST）を呼び、L-408（確認直後の誤クリック）に注意。

## 知見（手順 4）

- L-001: AI／適用の成否を呼び出し元が見る。失敗を成功扱いにしない
- L-044: 空メッセージ・過長・未知フィールドは 400。黙って truncate して成功にしない（切り詰め方針を採るなら明示）
- 秘密・上流エラーをクライアントへ出さない（既存 aiformat／refined）
- 文書正本: 契約は OpenAPI。README は入口のみ
- L-408: 「説明に反映」確認後のリピート入力抑止

## 受け入れ条件

1. アイテム詳細から会話でき、履歴が再読込後も残る
2. キー未設定時はチャットが明確に失敗し、設定画面に案内がある
3. 設定画面にアプリ集計の利用状況が見える
4. チャット API だけでは description／comments が変わらない。適用は明示操作
5. OpenAPI・update-api-doc 手順に従い契約が更新されている
6. ボード横断チャット・Admin Usage API・ツール実行は含まれない
