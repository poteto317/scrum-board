# 詳細から戻るとき一覧のスクロール位置を維持する（アイテム #15）

## 背景

詳細の「戻る」は常に `routerLink="/"` でボード先頭へ飛び、スクロールもリセットされる。ユーザーは元の高さ／位置から次のカードを確認したい。ボード縦はページ、横は `.board-scroll`。バックログは `.backlog-scroll`。Angular の `scrollPositionRestoration` は未設定で、カスタム容器の横スクロールはブラウザだけでは復元できない。

## 決めたこと

| 事項 | 採用 |
|------|------|
| 対象画面 | **ボード＋バックログ**（1A） |
| 復元する軸 | ボード: **ページ縦＋`.board-scroll` 横**。バックログ: **`.backlog-scroll` のみ**（ページ縦は対象外。リストが主スクロール）（2A） |
| 戻る先 | 一覧→詳細の直前に書いた `returnTo`（`'/'` \| `'/backlog'`）へ **`navigateByUrl`**。無ければ `/`。`history.back()` は使わない（3A の体感＝来た一覧へ戻る。中間履歴に依存しない実装に固定） |
| 復元の仕方 | **保存したスクロール位置**へ復元（4A）。対象カードへの強制 `scrollIntoView` はしない |
| 保存媒体 | `sessionStorage`（タブ単位） |
| 対象外 | 詳細内スクロールの復元、他サイトからの直リンク、ヘッダ Nav の特別扱い、ブラウザの戻る／進むによるスクロール復元、永続 localStorage、サーバー永続化、`history.back()` |

## 目的と受け入れ条件

1. ボードで縦・横にスクロールした状態からカード詳細へ入り、「戻る」で戻ると、縦・横ともおおよそ同じ位置に見える。
2. バックログから詳細へ入り「戻る」すると、バックログ一覧へ戻り、`.backlog-scroll` の位置が維持される（常にボード `/` へ飛ばない）。
3. `returnTo` が無い場合の「戻る」は `/`（ボード）へ行き、クラッシュしない。
4. 削除後の `navigate(['/'])` は従来どおりボードへ。**削除後はスクロール復元しない**（削除成功時に `scrumboard:scroll:board` と `list-return` を消す）。
5. Ctrl/Cmd 等での新規タブ遷移は既存のまま（保存しない）。同一タブの一覧→詳細の直前に位置と `returnTo` を保存する。
6. 詳細画面上の **一覧へ戻る UI はすべて**同じ戻る処理（ヘッダ・フッタの両方）。
7. 復元スケジュール後・適用前にユーザーがスクロールしたら、その回の復元は適用しない。コンポーネント破棄後の復元は適用しない（L-037 / L-040）。
8. 既存の DnD 自動スクロール・並べ替え・ライブ更新の挙動を壊さない。ライブ更新後にスクロールを再復元しない。数値復元のわずかなずれは許容（カードへの `scrollIntoView` はしない）。

## 保存する値（sessionStorage）

キー（定数化）:

| キー | 用途 |
|------|------|
| `scrumboard:list-return` | `{ "returnTo": "/" \| "/backlog" }`。詳細の戻る先。一覧→詳細の同一タブ遷移直前に上書き。 |
| `scrumboard:scroll:board` | `{ "scrollY": number, "scrollLeft": number }` |
| `scrumboard:scroll:backlog` | `{ "scrollTop": number, "scrollLeft": number }` |

- 不正 JSON・型不一致・必須フィールド欠損 → そのキーは無視（復元スキップ）。壊れた値で空オブジェクトを書き戻さない（L-002）。
- 数値は有限の number のみ採用。`NaN` / `Infinity` / 非 number は欠損扱い（無視）。負数は 0 にクランプして復元してよい。
- `returnTo` は詳細表示中のみ意味を持つ。詳細の戻る成功／削除成功で `scrumboard:list-return` を削除する。

## いつ保存するか（入口）

| 入口 | 動作 |
|------|------|
| ボード: カードのプライマリクリック → `router.navigate` | 直前に board スクロール＋`returnTo: '/'` |
| バックログ: 「詳細」リンク（現状 `routerLink`） | 同一タブ遷移になるようクリックで保存してから navigate（または同等）。修飾キー新規タブは保存しない |
| 一覧コンポーネント破棄 | **任意（保険）**: スクロールキーのみ更新。`list-return` は触らない。必須タスクにしない |

共有: 小さなモジュール（例: `list-scroll-session.ts`）に read/write/clear/parse を置き、ボード・バックログ・詳細から呼ぶ。

## いつ復元するか

- ボード／バックログの初回表示後（scroll 要素用意後）に **世代付き 1 回**適用（`afterNextRender` または同等）。破棄で世代を進め、古いコールバックは no-op。
- 適用直前に「ユーザーがすでにスクロールした」とみなせる場合（保存値から有意に動いている）はスキップ。
- 削除後のボード表示ではボード・スクロールキーを適用しない（AC 4）。

## 戻る UI（詳細）

| UI | 挙動 |
|----|------|
| ヘッダ `.back-link` | 共通 `goBackToList()` |
| フッタ「ボードに戻る」等 | 同じ `goBackToList()`（文言は `returnTo` に応じて「← バックログに戻る」／「← ボードに戻る」） |
| 削除成功後 | `list-return` と board スクロール保存を消し、`navigate(['/'])`（復元なし） |

`goBackToList()`: `list-return` を読み、`returnTo` が `'/'` \| `'/backlog'` なら `navigateByUrl` してキー削除。それ以外は `navigateByUrl('/')`。
## 知見（実装時）

- L-035: 復元はスクロール数値のみ。カード index に依存しない。
- L-037 / L-040: 復元はマウント時 1 回。遅延の古い復元でユーザー操作後のスクロールを上書きしない。
- L-002: 壊れた sessionStorage を空扱いで上書きしない。

## テスト

- 純関数: serialize/parse（不正入力は null）。
- ボード: navigate 前に位置が保存される。再表示で `scrollY` / `scrollLeft` が戻る。
- バックログ: `returnTo` が `/backlog` のとき詳細の戻るがバックログへ。
- 詳細: `returnTo` 無しなら `/`。削除後はスクロール復元しない。
- 回帰: modifier キーでの新規タブ、削除後の `/` 遷移。
