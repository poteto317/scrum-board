# カードごとのコマンド表示と任意の一括／新規初期セット

**前提:** [ワンクリックでコマンドを取得する](./2026-11-15-copy-command-templates-design.md)（グローバルカタログ）  
**日付:** 2026-11-15

## 目的

登録済みコマンド（カタログ）は全体で1つとしつつ、**各カードのコピーメニューに出すセットをカードごとに選べる**ようにする。あわせて、カタログ管理から任意で「全カードへ同じセットを付ける」「新規カードの初期セットにする」を実行できるようにする。いずれも必須ではなく、実行するまで既存の紐付けは変わらない。

## 受け入れ条件

- カタログ（名前＋本文）の CRUD は既存どおり。カード専用のテンプレート追加はしない
- 各カードはカタログから「このカードで出すコマンド」を選べる。未選択のカードのメニューは空（案内文のみ）
- カタログ管理でテンプレートにチェックを付け、任意ボタンで次を実行できる
  - **全カードに適用:** 全カードの表示セットを、チェックしたセットで**置き換え**（マージしない）
  - **新規の初期にする:** 新規カード作成時にコピーするデフォルトセットを、チェックしたセットで置き換え。既存カードは触らない
- カード新規作成時だけデフォルトを `card_command_templates` へコピーする。あとからデフォルトを変えても既存カードは追従しない
- カタログ削除時、そのテンプレートへの紐付けとデフォルトからも消える（幽霊行なし）
- バックログは対象外。紐付け変更はカード履歴に載せない

## 決めたこと

| 事項 | 採用 | 理由 |
| --- | --- | --- |
| カタログと表示の関係 | 全体カタログ1つ＋カードは選択のみ | 利用者選択（案1） |
| 未選択カード | メニュー空 | 利用者選択（案1） |
| 一括／新規の入口 | カタログ管理のチェック＋任意実行 | 利用者選択（案2） |
| 全カード適用 | 置き換え（マージしない） | 利用者選択（案2） |
| データ構造 | 紐付けテーブル＋デフォルトテーブル（方針 A） | カードとデフォルトを分離しやすい |
| デフォルトの意味 | 作成時コピーのみ（ライブ参照ではない） | 「未選択は空」と矛盾しない |

## データモデル

```sql
CREATE TABLE IF NOT EXISTS card_command_templates (
  card_id BIGINT NOT NULL,
  template_id BIGINT NOT NULL,
  position INT NOT NULL DEFAULT 0,
  PRIMARY KEY (card_id, template_id),
  FOREIGN KEY (card_id) REFERENCES cards(id) ON DELETE CASCADE,
  FOREIGN KEY (template_id) REFERENCES command_templates(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS command_template_defaults (
  template_id BIGINT NOT NULL PRIMARY KEY,
  position INT NOT NULL DEFAULT 0,
  FOREIGN KEY (template_id) REFERENCES command_templates(id) ON DELETE CASCADE
);
```

- `position` はメニュー表示順（同一カード／デフォルト内）。適用・PUT 時は body の配列順で採番する
- 既存の `command_templates` は変更しない
- 起動時マイグレーションでテーブルが無ければ作成（既存の `Initialize*` パターン）

## API

既存のカタログ CRUD（`/api/command-templates`）はそのまま。

| 方法 | パス | 内容 |
| --- | --- | --- |
| GET | `/api/cards/by-number/{n}/command-templates` | `{ "templates": [ { id, name, template, position }, ... ] }`（カード内 `position` 昇順）。Go ServeMux の衝突回避のため `{id}` パスは置かない（履歴 API と同様 by-number） |
| PUT | 同上 | body: `{ "templateIds": number[] }`。紐付けを置き換え → **200** + 上記と同じ一覧 |
| GET | `/api/command-template-defaults` | `{ "templateIds": number[] }`（`position` 昇順の id のみ） |
| PUT | `/api/command-template-defaults` | `{ "templateIds": number[] }` → **200** + 同じ形 |
| POST | `/api/command-templates/apply-to-all-cards` | `{ "templateIds": number[] }`。**全カード**の紐付けを置き換え（トランザクション）→ **204** |

### バリデーション

- カードが存在しない GET/PUT → **404**（空の紐付けと混同しない。L-002）
- `templateIds` 内の id が1件でもカタログに無い → **400**（部分適用しない）
- 重複 id → **順序を保って一意化**して受理
- 空配列は許可（カード／デフォルトを空にする。apply-to-all で全カードを空にする）
- 未知フィールド・型不正 → 400（既存方針）

### カード作成

`POST /api/cards`（および同等の作成経路）成功時、`command_template_defaults` の各行を新しい `card_id` の `card_command_templates` へコピーする。デフォルトが空なら紐付けも空。

### 埋め込まないもの

ボード JSON・カード JSON にテンプレート一覧を埋め込まない。ボードはコマンドメニューを開いたカードについてだけ GET する（開くたびに再取得してよい）。詳細は画面表示時に当該カード分を GET する。カタログ一覧は管理・カード選択 UI 用に既存どおり別 GET。

## UI

### カタログ管理（詳細の既存ダイアログを拡張）

- 各テンプレート行にチェックボックス
- 下部に任意ボタン:
  - 「全カードに適用」→ 確認ダイアログ（全カードの表示セットを選んだ内容で**置き換える**旨）→ `apply-to-all-cards`
  - 「新規の初期にする」→ 確認（既存カードは変わらない旨）→ `PUT defaults`
- チェックしたままボタンを押すまでサーバー状態は変わらない
- 成功／失敗は既存の admin メッセージ領域へ

### カードごとの選択（詳細画面）

- 「このカードで出すコマンド」チェックリスト（カタログから）。保存で当該カードの PUT
- 未保存の編集中表示と保存中 disabled は既存フォーム方針に合わせる

### コピーメニュー（ボード・詳細）

- **そのカードの紐付けだけ**表示。カタログ全件は出さない
- 0 件のとき: 「このカードにコマンドがありません。詳細画面で選べます。」（文言は短く固定）
- カード分の GET 失敗時は空案内ではなく通信エラー文言を出す（L-002）。成功の空配列だけが 0 件案内
- 詳細で「全カードに適用」成功後は、開いているカードの選択チェックリストを再取得する（L-039）
- コピー時の `{{url}}` 置換・成功／失敗フィードバックは既存どおり（L-801）

### 対象外画面

- バックログ

## エラー処理

- apply-to-all / PUT はトランザクション。失敗時ロールバック
- フロントは既存 `errorMessage`（通信失敗の定型文を含む）を表示
- カタログ DELETE は FK CASCADE または明示削除で紐付け・デフォルトも消す。メニューに幽霊行を残さない

## テスト

- 紐付け PUT／GET、デフォルト PUT／GET
- apply-to-all が全カードを置き換える（マージしない）。空配列で全カードが空になる
- カード作成時にデフォルトがコピーされ、その後デフォルトを変えても既存カードは変わらない
- カタログ削除で紐付け・デフォルトから消える
- 不正 id → 400、重複は一意化
- FE: メニューがカード紐付けのみ／管理ボタン未実行では変えない／確認ダイアログ後にだけ API が飛ぶ

## 対象外

- バックログ
- カード履歴への紐付け記録
- テンプレートのシェル実行・サーバー側置換
- ライブ「デフォルト追従」（未カスタムカードがデフォルト変更に追従する方式）
