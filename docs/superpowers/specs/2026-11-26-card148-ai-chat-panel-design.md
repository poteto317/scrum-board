# AIチャットの欄を大きくする（#148）設計

## 背景

カード #148「AIチャットの欄を大きくする」:

> NotionやVS Code、CursorのIDE版のチャットのように、右側のパネル表示にする。
>
> また、全画面のようなアイコンを表示し、専用のチャット画面へ遷移できるようにもする。

現状（#146 後）:

- 右下の FAB（`AiChatFab`）が開くと、幅 `min(24rem, …)`・高さ最大 `70vh` の浮きパネルに `ProjectAiChat` が入る。
- 専用ルートは無い。API・履歴・送信ロジックはプロジェクト単位で既に揃っている。

問題は **表示の大きさ・置き方** だけ。バックエンドやメッセージ API は変えない。

## 決めたこと

カード本文（右パネル＋全画面画面）と下表は **本設計で確定**する。差し替えは別カードとする。

| 論点 | 採用 | 捨てた案 |
| --- | --- | --- |
| 右パネルの形 | 画面右端の **フルハイト・ドック**（メインを押し縮める） | いまの浮きカードを大きくするだけ／全面オーバーレイ |
| 幅 | 下記「レイアウト」の式 | リサイズハンドル（範囲外） |
| 専用画面 | ルート **`/ai-chat`**（`authGuard`）。選択中プロジェクトの履歴 | `/projects/:id/ai-chat`（URL とシェルの project 切替が二重になる） |
| 全画面アイコン | ドックのヘッダーに置く。押すと `/ai-chat` へ遷移しドックは閉じる | モーダル全画面（ルート無し） |
| FAB | 残す（開閉トグル）。ドックが開いている間も入口は「閉じる」相当の `aria-expanded` | FAB 廃止してヘッダー専用ボタン |
| アイテム詳細の文脈 | ドックではいまどおり `focusItem`。専用画面では **フォーカス無し**（プロジェクト全体）。未送信下書きは遷移で失ってよい（履歴はサーバ） | クエリで focus を持ち越す |
| API | **変更なし** | 新エンドポイント |

### レイアウト

- ドック幅（CSS）:
  - 既定（`min-width: 640px`）: `width: min(28rem, 40vw);`
  - 狭い画面（`max-width: 639px`）: `width: min(100vw, 28rem);`（ビューポート基準。サイドバーは重ねてよい）
- ドックが開いているとき、シェルにクラス `ai-chat-dock-open` を付け、**`.app-main` にだけ `padding-right` をドック幅と同じ値**で足す（`.app-body` や `margin-right` は使わない）。幅は CSS 変数 `--ai-chat-dock-width` をドックと `padding-right` で共有する。
- ドック自体は `position: fixed; top: 67px; right: 0; bottom: 0;`（ヘッダー高さは既存 sticky ヘッダーと同じ 67px）。
- **z-index**: ヘッダー `5` ＜ サイドバー（既存）＜ ドック **`12`** ＝ いまの FAB ルートと同じ層。FAB 入口ボタンはドックより前面に見えるようドック内ではなくルート直下に置き、入口は **`13`**。ダイアログ（`<dialog open>`）より下に留める（既存 Esc ガードと整合）。
- ドック内はヘッダー（タイトル・全画面・閉じる）＋ `app-project-ai-chat` が残り高さを使う。メッセージ一覧の `max-height: 28rem` はドック／専用画面では **フレックスで伸びる** ように変える。`ProjectAiChat` に `layout: 'dock' | 'page'` を渡し、CSS で切り替える。

### ルートと入口

- `app.routes.ts` に `{ path: 'ai-chat', loadComponent: … AiChatPage, canActivate: [authGuard] }` を追加する。未ログインは既存どおりログインへリダイレクトし、**ページ内の未ログイン案内は出さない**。
- `isAiChatRoute` は **ドック FAB を出すルート** のまま（`/`・`/backlog`・`/items/:n`）。`/ai-chat` では FAB を出さず、専用ページだけがチャットを描画する。
- `AiChatPage` の表示は次の 3 状態（L-990）:
  1. **待機**: `!bootstrapped()` または `switching()` → 読み込み中の短い表示（チャット本体も「未選択案内」も出さない）。
  2. **案内**: `bootstrapped() && !switching() && !(activeId() > 0)` → プロジェクト未選択の案内。
  3. **本体**: `bootstrapped() && !switching() && activeId() > 0` → `ProjectAiChat` を `layout="page"` で表示。
- **戻る**: ページ内の「戻る」リンクのみが対象。`history.length > 1` なら `Location.back()`、なければ `/`。ブラウザの戻るボタンは通常の履歴どおり（追加のフックなし）。ヘッダーの他ナビは通常遷移。深リンクで直開きしたときは「戻る」で `/` に行く。
- ページ初回で本体が表示されたら、見出しまたは「戻る」リンクへフォーカスを移す（L-157 / L-397。ドック閉鎖でフォーカスが body に落ちたままにしない）。

### 開閉・フォーカス・キーボード（既存パターンを踏襲）

- 開く／閉じるのキーリピートガード（`OPEN_GUARD_MS` / `CLOSE_GUARD_MS`）、Esc で閉じる、閉じたあと入口へフォーカス復帰は現状の `AiChatFab` を維持する（L-408 / L-397 / L-157）。
- 全画面ボタン: 押下直後はボタンを disabled にし、`router.navigate(['/ai-chat'], { queryParams: { project: <チャット中の projectId> } })` の **成功後だけ** ドックを閉じる。失敗時はドックを開いたまま・ボタンを再び有効にする（L-001 / L-058 と L-408 の両立。遷移前に先に閉じない）。専用画面は `?project=` を優先し、無ければ `activeId`（アイテム詳細のプロジェクトとヘッダー選択が違うときも履歴が食い違わない）。
- ドキュメント全体のショートカット判定は、入力中（textarea）を誤って閉じない既存 Esc 条件を崩さない（L-522）。

### 状態の置き場

- ドックの開閉は **`AiChatFab` の `open` signal が正**（新サービスは作らない。`AiChatContext` に `dockOpen` を複製しない。L-542）。
- シェルの押し縮めクラスは、`app` が `@if` / `viewChild` で載せている `AiChatFab` の `open()` を参照して付ける（例: `#aiChatFab` と `aiChatFab.open()`）。ページ固有の下書きや選択は載せない。
- プロジェクト切替でドックを閉じる挙動は現状どおり。

### CSS スコープ（L-792）

- ドック用クラスはコンポーネント CSS（`ai-chat-fab.css` / 新 `ai-chat-page.css` / `project-ai-chat.css`）に置き、グローバルへ祖先無しで移さない。シェル側の `padding-right` は `app.css` で祖先付きセレクタにする（例: `.app-body.ai-chat-dock-open .app-main`）。

### 成否の扱い（L-001 / L-058）

- `/ai-chat` へのナビ失敗時はドックを開いたままにし、専用画面へ行ったつもりにしない（上記「全画面ボタン」）。
- 専用画面でプロジェクト未選択は、空の成功表示にせず案内を出す（未ログインはガード任せ）。

## 受け入れ条件

1. ボード・バックログ・アイテム詳細で「AIに聞く」を開くと、右端フルハイトのドックにチャットが出て、メイン領域が隠れない（押し縮め）。
2. ドックの幅は、いまの浮きパネル（約 24rem・70vh）より明らかに大きい。
3. ドックヘッダーに全画面（拡大）コントロールがあり、押すと `/ai-chat` へ遷移し、同じプロジェクトの履歴が見える。
4. `/ai-chat` では FAB が出ず、チャットがページ本体として使える。ページ内の「戻る」で、履歴があれば前画面、深リンク直開きなら `/` に戻れる。未ログインはログインへリダイレクトされる。
5. アイテム詳細からドックで聞いたとき、これまでどおり `focusItem` と「説明に反映」「コメント追加」が使える。専用画面ではフォーカス無し。
6. Esc・開閉のフォーカス・プロジェクト切替で閉じる、既存の安全策が退行しない。
7. API・DB・OpenAPI に変更が無い。
8. 既存の `project-ai-chat` / `ai-chat-fab` 系テストを更新し、ドック開閉・`/ai-chat` 表示・ナビの失敗でドックが残ることを固定する。

## 範囲外

- パネル幅のドラッグリサイズ、分割ビューの永続化。
- 回答のストリーミング。
- アイテム単位 AI API の削除。
- モバイル専用の別 UI キット（狭い画面はドック幅の拡大で足りるものとする）。
