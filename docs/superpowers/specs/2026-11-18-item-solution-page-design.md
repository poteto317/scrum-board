# アイテム・ソリューションページ設計（アイテム #19）

## 背景

実装後（必要なら実装前）に「どう実装したか」を整理する場所が欲しい。詳細の description に混ぜず、**別ページ**に書き、詳細からはそのページへのリンクをプロパティとして持つ。

カード要件:

- ソリューションを記載したページへのリンクをセットするプロパティ
- 基本は実装後に記載。整理のため実装前に入れる場合もある
- 詳細に本文を埋め込まず、別ページとして作り、それをプロパティとして持てる

## 決めたこと

| 事項 | 採用 |
|------|------|
| 保存場所 | アイテム列 **`solution`（string / TEXT）**。未設定相当は `""`（1A） |
| 別ページ | アプリ内ルート **`/items/:number/solution`**（`?project=` は詳細と同じ）。外部 URL 専用プロパティにはしない（2A） |
| プロパティ | 詳細のプロパティ欄に **ソリューションへのリンク**（常時表示）。本文編集は詳細ではしない（3A） |
| 空のとき | 別ページは常に開ける。空なら未記入プレースホルダ＋編集 UI。プロパティリンク文言は **空なら「ソリューション（未記入）」／非空なら「ソリューション」**（4A） |
| 編集 UI | ソリューションページ上で **description と同じブロックエディタ**を再利用し、**デバウンス自動保存**（5A） |
| 履歴 | `solution` の新規／変更を履歴 `changes` に残す。UI 表示名は「ソリューション」（6A） |
| ボード／一覧 | **表示しない**（初版）。詳細プロパティとソリューションページのみ（7A） |
| 削除 | 専用「ソリューション削除」は無し。空文字保存で未記入に戻す（8A） |
| MCP | 本機能のスコープ外。既存 MCP が Item JSON をそのまま返すなら追従するが、専用ツール追加はしない |

## 目的と受け入れ条件

1. アイテム JSON に `solution: string` がある（未設定相当は `""`）。ボード／詳細／by-number の GET に含める。
2. `PATCH /api/items/{id}` で `solution` を部分更新できる（by-number の本文 PATCH エンドポイントは作らない。取得は既存 `GET .../by-number/{n}`）。キー省略は変更しない。JSON `null` は description と同様 `*string` デコードで **変更なし**（クリアは `""` を送る。クライアントは `null` を送らない。L-002 / L-454）。
3. 検証は description と同じ: UTF-8 妥当かつ **Unicode 文字数（rune）≤ 10000**。内容の trim はしない（前後空白・改行も本文として保存）。超過・不正 UTF-8 は 400。
4. `POST /api/items` 作成時も任意で `solution` を受け付ける（省略時 `""`）。作成 UI からの入力は初版対象外（API のみ可）。
5. ルート `/items/:number/solution` でソリューションを表示・編集できる。`?project=` 解決は詳細と同じ（番号はプロジェクト内番号）。
6. 詳細プロパティ欄にソリューションへのリンクがある。クリックでソリューションページへ遷移する。リンク文言は決めたこと 4A のとおり。
7. ソリューションページでの編集は自動保存。保存失敗時は成功扱いにせず、エラーを出し、未保存下書きを捨てない（L-001）。
8. ライブ再取得中にソリューションを編集中なら、未保存下書きを古い GET で上書きしない（L-037 / L-040）。
9. `solution` が変わったとき履歴に `updated`（field: `solution`）が付く。未変更なら履歴を増やさない。履歴 UI の表示名は **「ソリューション」**（`item-history` の labels に必須追加）。
10. 初期スキーマと既存 DB の両方で列が追加され、既存行は `""`。
11. 詳細の description 本文・既存プロパティ（PR / 関連）の挙動は変えない。

## 用語

- **ソリューション**: アイテムに紐づく実装整理用の本文。description とは別フィールド。
- **ソリューションページ**: `/items/:number/solution` の画面。閲覧と編集の場。
- **ソリューションプロパティ**: 詳細サイドバーの、ソリューションページへのリンク行。

## 永続化

- DB: `items.solution TEXT NOT NULL`（DEFAULT `''`）。起動時マイグレーション `InitializeSolution` で不足時に `ADD COLUMN`（`close_reason` と同型）。
- `database/init/001_schema.sql` にも同列を追加する。
- API フィールド名は camelCase `solution`。旧キーや別名は未知として 400。
- モデル: `Item` / `ItemInput` / `ItemPatch` に `Solution` を追加。`cardFields`・INSERT・UPDATE・scan を追随。
- 別テーブルは作らない（1 アイテム 1 本文で足りる）。

## API

- 読み取り: 既存の item / board レスポンスに `solution` を載せる。欠落時は常に `""`（null にしない）。
- 書き込み: `ItemPatch.Solution *string`。省略＝触らない。`""`＝未記入にクリア。
- 専用 REST エンドポイントは作らない（既存 PATCH で足りる）。
- `PATCH .../status` は現状どおり `status` のみ（ソリューションは触らない）。

## クライアント

### ルーティング

- `app.routes.ts` に `items/:number/solution` を追加（`cards/...` リダイレクトは詳細と同様にあってもよいが必須ではない）。
- `canDeactivate` は詳細と同様、未保存フラッシュを保証する。

### ソリューションページ

- 新規コンポーネント（例: `ItemSolution`）。タイトル行にアイテム番号・タイトルへの戻るリンク（詳細へ）。
- 本文は description と同じブロックエディタ／レンダラを再利用（保存先フィールドだけ `solution`）。
- 取得: `api.itemByNumber`。保存: 既存 autosave パターンで `solution` のみ PATCH（他フィールドを undefined マージで消さない。L-454）。
- 詳細の form とは別インスタンス。`solution` は **ソリューションページの form のみ**に置き、詳細の **`fields` にも `sideFields` にも入れない**（dueAt 型の side 更新に載せない。L-453 / L-790）。

### 詳細プロパティ

- PR / 関連の近くに「ソリューション」行を追加。
- リンク先: `routerLink`=`/items/{number}/solution` ＋ `queryParams.project`（既存 `itemAppPath` は詳細用のまま。必要なら `itemSolutionPath` ヘルパーを追加してよい）。
- リンク文言: `solution === ''` なら「ソリューション（未記入）」、それ以外は「ソリューション」。本文プレビューは出さない（詳細に埋め込まない）。
- プロパティから本文モーダル編集はしない。

### ボード／バックログ

- 変更なし（バッジ・プレビューなし）。

## 履歴

- `solution` の値が変わったときだけ `field: "solution"` の変更を履歴に追加（description と同様）。
- 履歴 UI 表示名は「ソリューション」（受け入れ条件 9）。

## 対象外

- 外部 URL をソリューション先として設定する機能
- 複数ソリューション／版管理／テンプレート
- ボード上のソリューション有無バッジ
- description からの自動生成・AI 要約
- MCP 専用ツールの追加
- ソリューションの必須化や Close/Done 時の強制入力

## 知見（実装時）

- L-001: 保存成否を見てから成功扱い。失敗時に UI を確定しない。
- L-002: 未設定と空を `""` で統一。null クリアに頼らない。
- L-037 / L-040: ライブ再取得と編集世代ガード（詳細と同趣旨をソリューションページにも）。
- L-453: 詳細で独立した複数更新を連続呼び出しして古いクロージャが上書きしないよう、`solution` を詳細の side 更新経路に載せない。
- L-790: form flush 応答が side の dirty を潰さない既存規則。`solution` を詳細 `sideFields` に入れないことで本機能側の関与を避ける。
- L-454: PATCH ペイロードで省略と undefined マージを混同しない。
- L-015: ソリューション保存が description / prUrls / relatedItems を暗黙に書き換えないこと。

## 推奨案の根拠（確認待ちにしない事項）

feature.md 手順 5・7 に従い、次を推奨案として採用済みとする。

- 外部 URL プロパティ案は「別ページを作る」要件を満たさないため不採用。
- 別テーブル案は 1:1 本文には過剰なため不採用。
- 詳細内埋め込みエディタ案はカードの「詳細に直接含めない」に反するため不採用。
