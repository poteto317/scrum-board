# アイテム追加ダイアログの誤閉じ防止

## 背景

カード #40「アイテムを追加する際、操作ミスで閉じてしまう」。ボード／バックログの「アイテムを追加」ダイアログは、外側（backdrop）クリックで閉じ、下部に「キャンセル」がある。入力中に誤って外をクリックしたりキャンセルを押したりすると下書きが消える。右上の × で閉じれば足りる。

## 決めたこと

| 事項 | 採用 | 理由 |
|------|------|------|
| 対象画面 | ボードの追加ダイアログ（カード／列）とバックログの「アイテムを追加」 | カード文面はアイテム追加。ボードはカード／列で同一 `<dialog>` を共有するため外側クリック無効は両方に効く。列側のキャンセルも同じ誤押しがあるため同様に削除。詳細の削除確認・コマンド管理など他ダイアログは対象外 |
| 外側クリック | 閉じない | 誤閉じの主因。`(click)="close()"` を dialog から外す |
| 下部キャンセル | 削除 | 誤押ししやすい。× と Esc で代替 |
| Esc | 閉じる（維持） | 意図したキーボード操作。`(cancel)` と section の `keydown.escape` は現状どおり |
| ×（閉じる） | 維持 | 明示的な閉じる入口。保存中は既存どおり disabled |
| 保存中の外側 | 対象外 | 外側ではそもそも閉じないため追加ガード不要 |
| API / DB | 変更なし | UI のみ |

## 現状

- `board.html` / `backlog.html`: `<dialog (click)="close()">` + 内側 `stopPropagation`、下部「キャンセル」、ヘッダー ×、`(cancel)` で Esc 閉じ
- `Modal` ディレクティブは `showModal()` のみ。外側閉じはテンプレート側

## 振る舞い

1. 追加ダイアログを開く
2. ダイアログ外（backdrop）をクリックしても閉じない。フォーム内容は残る
3. 「キャンセル」ボタンは無い
4. × または Esc で閉じる（保存中は × disabled、既存どおり）
5. 送信成功後は既存どおり閉じる

## 実装方針

- `board.html` / `backlog.html` の対象 dialog から `(click)="close()"` を削除。内側の `stopPropagation` は不要なら残してもよい（害なし）
- 対象フォームの「キャンセル」ボタンを削除。`form-actions` は主ボタンのみ
- 他モーダル（削除確認、コマンド管理）は触らない
- コンポーネント TS / API 変更なし

## テスト

- ボード: カード追加ダイアログを開き backdrop 相当の dialog クリックで `modal()` が残ること、キャンセル文言が無いこと、× で閉じること
- ボード: 列追加も同様（共有 dialog）
- バックログ: 同様
- Esc 閉じは既存挙動を壊さないことを確認（必要なら明示テスト）
- 既存の追加成功・バリデーション・保存中テストは維持

## 知見

- L-408: ダイアログ開閉と誤入力の続き（今回は外側クリック／キャンセル誤押しが主題。リピート対策はスコープ外で既存のまま）
- L-002: 今回は該当なし（「無い／失敗」と「空」の取り違えは扱わない）

## 対象外

- 詳細画面の削除確認・コマンド管理ダイアログの外側クリック／キャンセル
- フォーカス・Esc の挙動変更（維持）
- デザインの見た目変更（余白の微調整以外は不要）

## 検証

- `ng test`（board / backlog 関連）
- 手動: ボードとバックログで入力中に外側クリックしても残る、キャンセルが無い、×／Esc で閉じる
