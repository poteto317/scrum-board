# かんばん／バックログのフィルタ分離（アイテム #63）

## 背景

カード要件:

- かんばんとバックログのフィルタリングは分ける。
- 理由: バックログでは Todo をメインにしたいが、かんばんボードでは常に全てのステータスを表示したい。

現状（#23 一覧フィルタ）: `ListFilterSession`（`providedIn: 'root'`）と `GET/PUT /api/list-filter` が **ワークスペース共通 1 件**。ボードとバックログが同じ `query` / `statusIds` を共有するため、バックログで Todo だけに絞るとボードでも列が隠れる（逆も同様）。空の `statusIds`＝全列、という意味は維持する。

## 決めたこと

| 事項 | 採用 |
|------|------|
| 分離の単位 | **1A** API 永続をボード用・バックログ用で独立 |
| ボード初期 | **全ステータス**（`statusIds: []`＝全列） |
| バックログ初期 | **Todo 列のみ**選択（列名が `Todo` の columnId） |
| テキスト `query` | **3A** 画面ごとに独立 |
| 既存データの移行 | **4B** 現行 1 件 → **ボード側**へ。バックログは Todo 初期 |
| 適用場所 | 従来どおり **FE がクライアント側で絞る**（一覧 API は変えない） |
| マッチ規則 | 既存どおり（query 部分一致 AND、空 statusIds＝全列） |

未回答だった 1・3・4 は推奨を採用。2 はユーザー指示どおり（ボード＝全て／バックログ＝Todo 初期）。

## 目的と受け入れ条件

1. ボードのフィルタ変更がバックログの表示に影響しない。逆も同様。
2. **未設定の初期値**（新規行・旧形からの移行で backlog を初めて埋めるとき）: ボード側は移行規則 4B に従う（旧値があればそれを引き継ぎ、無ければ `statusIds: []`＝全列）。バックログ側は **Todo 初期**（下記「Todo 列の解決」）。「移行直後にボードが必ず全列」ではない（旧フィルタが非空ならボードに残る）。
3. 各画面の `query` と `statusIds` は別々にサーバーへ保存され、再読込・別端末でも同じ画面では同じ状態になる。
4. クリア操作はその画面のフィルタだけを空（全列・空 query）にし、もう一方は変えない。クリア後の空 `statusIds` は「全列」であり、再 GET で Todo を再シードしない。
5. Todo 列が存在しない／改名されて ID が消えた場合: バックログの `statusIds` は既存正規化どおり無効 ID を落とし、結果が空なら全列表示（クラッシュしない）。
6. ボード↔バックログ遷移で、相手画面のドラフトを上書きしない（画面ごとのドラフト／confirmed）。
7. 既存の世代ガード・デバウンス PUT・GET 失敗表示・壊れた JSON を空で上書きしない、という #23 の安全要件を両ビューで維持する（L-001 / L-002 / L-037 / L-040）。
8. フィルタ中の DnD／並べ替え安全性（非表示アイテムを操作対象に出さない）は各画面の現行規則を維持（L-460 / L-472）。

## API

### 応答形（推奨）

`GET` / `PUT /api/list-filter` のボディを次に拡張する（パスは維持し、破壊的な別エンドポイントは作らない）。

```json
{
  "board": { "query": "", "statusIds": [] },
  "backlog": { "query": "", "statusIds": [1] }
}
```

- PUT は **全体置換**（`board` と `backlog` の両方必須）。片方だけ送る部分更新は初版対象外（クライアントは常に両キーを持つオブジェクトを送る）。
- 各ネストの検証は現行 `ListFilter` と同じ（query trim・200 文字、statusIds 正整数・重複除去・未知列 ID 無視、未知トップレベル／ネストキーは 400）。
- GET で行が無い・壊れた JSON: 両ビューとも安全なデフォルトを返す（下の移行・初期化）。壊れた行を空オブジェクトで上書きしない（読み取り時）。

### ストレージ

- 既存 `workspace_list_filter` を拡張する（例: `board_query` / `board_status_ids` / `backlog_query` / `backlog_status_ids`、または JSON 1 カラムで両ビュー）。実装プランで DDL を具体化する。
- シングルトン `id = 1` は維持。

### Todo 列の解決

- 照合: 列名を trim したうえで **大文字小文字を区別しない** `"todo"` 一致（シード列名 `Todo` と、利用者が付けた `TODO` 等を拾う）。
- 複数ヒット: **position 昇順で最初の 1 件**の ID を使う。
- 0 件: `statusIds: []`（全列）。エラーにしない。

### 初期シードの発火（クリアと区別）

Todo 埋めは次のとき **一度だけ**行う。空 `statusIds`（ユーザーがクリアした全列）では再実行しない。

| 状況 | board | backlog |
|------|-------|---------|
| 新テーブル／行なし | `{query:"",statusIds:[]}` | Todo 初期（上記） |
| 旧形 1 件からの移行 | 旧 query/statusIds をコピー | Todo 初期 |
| 新形で両キー保存済み | 保存値（正規化のみ） | 保存値（正規化のみ）。`[]` のままなら全列 |
| 壊れた JSON の GET | 安全デフォルト（上と同趣旨）を返す。**行を空で上書きしない** | 同左 |

シード結果を永続化するのは **マイグレーションまたは移行用の書き込みパス**（プランで一本化）。通常の GET は読取のみで、クリア後の `[]` を Todo に戻さない。

### 移行（4B）

1. 旧形（単一 `query_text` + `status_ids`）があれば **`board` にコピー**。
2. **`backlog`**: query 空＋Todo 初期（上記）。Todo 列が無ければ `[]`。
3. 旧カラムは移行後に削除または読まない（プランで一本化）。二重の意味のソースを残さない。

## クライアント

- `ListFilterSession` を **ビュー付き**にする（例: `filterFor('board' | 'backlog')`、または board／backlog それぞれの signal）。
- ボード画面は `board` だけ読み書き。バックログ画面は `backlog` だけ。ナビ時に相手の dirty を消さない／上書きしない。
- デバウンス PUT は **両方の最新ドラフトを載せた全体**を送る（サーバーが全体置換のため）。送信中に片方だけ古い confirmed を混ぜないよう、メモリ上の両ビューをソースにする。
- UI: 既存 `ListFilterBar` を流用。渡す session／view だけ変える。
- Todo 初期は **サーバーが移行／初期行で埋めた応答**を使う。クライアントが列名から推測して初回だけ PUT しない。表示正規化は従来どおり既知列 ID に制限。

## テスト方針

- BE: GET/PUT 新形、旧形からの移行（既存値→board、backlog=Todo）、検証 400、壊れた JSON、Todo 欠如時。
- FE: ボードで変えた status／query がバックログに効かないこと（逆も）。クリアが片側だけ。遷移時の dirty 分離。既存 match／active 純関数は共有のまま。
- 回帰: ボード／バックログのフィルタ＋DnD 関連スペック。
- マニュアル: バックログで Todo のみ → ボードへ移動しても **ボード側フィルタは独立**（移行後は旧 board 値、または未設定なら全列）。ボードで絞る → バックログの Todo 初期／独自設定が保たれる。

## 知見

| ID | 扱い |
|----|------|
| L-001 / L-002 | PUT 成否と GET 失敗を空成功と取り違えない。壊れた prefs を空で上書きしない |
| L-037 / L-040 | 両ビューの load/save 世代ガード。古い応答で新しい入力を潰さない |
| L-110 | 画面ごとの状態を root の単一 signal に畳まない |
| L-460 / L-472 | フィルタ後配列での並び替え・DnD を壊さない |
| L-015 | クリアや移行で、表示していない画面の prefs を暗黙に消さない（4B の board 引き継ぎを守る） |

## 対象外

- ユーザー別・端末別 prefs
- サーバー側一覧クエリ絞り込み
- view クエリパラメータ方式の別 API
- PUT の部分更新（片キーのみ）
- Todo 以外の「スマート初期」（例: Review だけ）
- URL クエリとの双方向同期
