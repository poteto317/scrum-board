# プロジェクト切替後に別プロジェクトのアイテムが残る（#71）

## 背景

カード: 画面上、プロジェクト切替後に別プロジェクトのアイテムが残って見えることがある。原因調査のうえ修正する。

関連: 既存対策は役割が分かれている — L-040（世代で古い GET を捨てる・切替中 poll 抑制）、L-842（busy を楽観更新より先に立てる）、L-844（切替 busy 中の作成・layout・DnD 拒否）。いずれも「表示中の items が active と一致しているか」までは保証していない。

## 調査結果（原因）

1. `ProjectSession.switchTo` は PATCH 前に `activeId` を楽観更新する（`project-session.ts`）。
2. Board / Backlog の `data().items` は、切替後の `GET /api/board`（または backlog）が成功するまで**旧プロジェクトの配列のまま**。
3. FE の `grouped` / 一覧は **projectId で絞らない**（サーバの active スコープ結果をそのまま表示する前提）。
4. そのため切替〜再取得完了までの間、ヘッダーは新プロジェクトなのにカードは旧プロジェクトのまま見える。再取得が遅い・失敗すると「時々残る」ように感じる。
5. 再取得失敗時も `finalize` で `endSwitch()` するため、`activeId` は新・`items` は旧のまま残る（次の poll まで）。**本カードの修正対象は表示の食い違い**であり、GET 失敗後の操作可否の強化は非目標（既存の L-844 ガードは切替 busy 中のみ）。

再現（論理）:

1. プロジェクト A のボードを表示する。
2. ヘッダーでプロジェクト B に切り替える。
3. 再取得完了前（または再取得失敗直後）にボードを見る → A のアイテムが残って見える。

## 決めたこと

| 事項 | 採用 |
|------|------|
| 修正方針 | **表示時に `projectId === activeId` で絞る**（Board / Backlog）。切替中も失敗後も、active と違うカードは出さない |
| データクリア | `data()` を空にする必須クリアはしない。**settings PATCH 失敗時**は既存どおり `activeId` を切替前に戻すので旧 items が再び一致して復旧する。**再取得（GET）失敗時**は `activeId` を戻さず、フィルタで旧カードを隠す（受け入れ条件 2）。成功時は GET で差し替え |
| API | 変更しない（サーバは既に active で絞っている） |
| 範囲 | Board と Backlog の一覧表示。item-detail の所属変更 UI は対象外 |

### 検討したが採らなかった案

- **切替開始で items を [] に破壊的クリア**: 失敗時に空のままになりやすく、復旧が poll 頼み。フィルタの方が安全。
- **再取得失敗で activeId を巻き戻す**: PATCH は成功しているためサーバ active と食い違う。表示フィルタで足りる。

## 目的と受け入れ条件

1. プロジェクトを切り替えた直後（再取得完了前）に、旧プロジェクトのカードが一覧に出ない。
2. 切替後の再取得が失敗しても、旧プロジェクトのカードは出ない（エラー表示は既存どおり可）。
3. 切替成功後は新プロジェクトのカードだけが出る（既存の世代無視・poll 抑制は維持）。
4. ユニットテストで「activeId だけ先に変わったとき旧 projectId のカードが grouped / backlog 一覧に出ない」を固定する。
5. Go API・DB スキーマは変更しない。

## 非目標

- プロジェクト切替 UX の全面刷新（スケルトン等）
- item-detail からの所属移動フローの変更
- サーバ側 Board API の契約変更
- GET 失敗後（`endSwitch` 後）の作成・DnD など操作ガードの追加強化（表示フィルタでカードは隠す）

## 関連知見

- L-040: 古い非同期結果の上書き（既存の generation / 切替中 poll 抑制は維持）
- L-842: 楽観更新と busy の順序（既存）
- L-844: 切替 busy 中の作成・layout・DnD 拒否（既存。本修正は表示フィルタで所属不一致カードを隠す）
