# 説明ブロックのプレースホルダーを消す（アイテム #65）

## 背景

カード要件: 詳細の説明で改行して空行を入れても、各空ブロックにプレースホルダー（「背景、取り組む内容、完了の条件など」）が出続け、空行を入れる意味が薄い。

現状: `DescriptionBlocksEditor` はブロックごとの `textarea` に固定の `placeholder` を付けている。ブラウザは `value === ''` のときだけ `::placeholder` を描画するため、Enter でできた空ブロック（`''`）にも同じヒントが出る（`parse` / `split` で空行は `''` として保持する仕様は #21 のまま）。

## 決めたこと（推奨案を採用）

設計の確認事項は推奨案つきでまとめて問う想定だが、本フローでは未回答を承認とせず推奨を採用して確定する（feature.md）。

| 事項 | 採用 |
|------|------|
| 対象範囲 | **詳細画面の説明ブロック編集のみ**（`description-blocks-editor`）。ボード／バックログの作成モーダル説明 textarea の placeholder は変更しない（#21 と同じ切り分け） |
| 振る舞い | ブロック `textarea` から **`placeholder` 属性を削除**する（タイトル文言「消す」に合わせる）。条件付き表示（先頭空ブロックだけ出す等）はしない |
| アクセシビリティ | 既存の `[attr.aria-label]="'説明ブロック ' + ($index + 1)"` は残す。placeholder のみを頼りにしない（L-554） |
| データ／API | 変更なし。`description` string・ブロック分割／結合・autosave はそのまま |
| 見た目 CSS | `::placeholder` 用の色指定は残っても害はないが、未使用なら当該セレクタの削除は任意（必須ではない） |

### 検討したが採らなかった案

- **空の説明（ブロックが `['']` のときだけ）placeholder を出す**: 初回ヒントは残るが、カード文言は「消す」。実装も分岐が増える。
- **作成モーダルの placeholder も消す**: カードは詳細の空行問題。作成は単一 textarea で空行＝同一欄内のため今回の対象外。

## 目的と受け入れ条件

1. 詳細の説明ブロック（空ブロック含む）に、案内用の placeholder 文字列が表示されない。
2. Enter で空行（空ブロック）を増やしても、各行にヒント文言が出ない。
3. ブロック分割・結合・IME・貼付・文字数上限・autosave の既存挙動は変わらない。
4. 作成モーダル（board / backlog）の説明 placeholder は従来どおり残る。
5. 各ブロック textarea は `aria-label` で識別できる（placeholder 削除後も支援技術向けの名前がある）。

## 非目標

- 作成フォームの placeholder 変更
- ブロックモデル／シリアライズの変更
- タイトル入力の placeholder 変更
- 新規のヒント UI（ツールチップ・空状態バナー等）の追加

## 実装方針（概要）

- `frontend/src/app/description-blocks-editor.html` の `placeholder="…"` を削除する。
- テスト: ブロック editor の DOM に当該 placeholder が無いこと、および末尾空ブロック（`a\n` → `['a','']`）にも付かないことを固定する。Enter 分割自体は既存テストに委譲する。

## 関連知見

- L-456: マイグレーションや識別子の上書きは今回なし
- #21 borderless blocks: 空行 = `''` ブロック保持は維持
