# カード詳細の PR / 関連の並び替え UI（カード #37）

## 背景

カード詳細では GitHub PR（`prUrls`）と関連アイテム（`relatedItems`）を追加・削除できる。どちらもサーバは配列順＝`position` で永続化済みだが、詳細 UI に並び替え操作が無い。

カード #37 の文言は PR 並び替えだが、設計選択で **関連一覧の並び替えも同スコープ** とする（#28 設計の「関連 DnD は v1 対象外」を、本カードで解禁する）。

## 決めたこと

| 事項 | 採用 |
|------|------|
| 対象一覧 | **PR 一覧と関連一覧の両方**（ボード面・バックログは対象外） |
| 操作 | **CDK ドラッグ＆ドロップ**（ハンドル）＋ **上下ボタン**（キーボード／補助） |
| 保存 | 並び替えのたびに既存の即時 `PATCH`（`prUrls` / `relatedItems` の **全置換**）。専用 reorder API は作らない |
| 保存中 | その一覧の `saving()` 中は DnD・上下・追加・削除を無効化（既存の追加削除と同じ直列）。PR 保存中でも関連は操作可（逆も同様） |
| 失敗時 | **楽観的に一覧を仮並び替え**し、失敗したら操作前の配列に戻してエラー表示 |
| 履歴 | 既存フィールド名のまま。配列順が変われば `prUrls` / `relatedItems` の before/after が1件増える。専用「並び替え」ラベルは作らない |
| 双方向関連 | **所有者カードの順序だけ**を変える。相手カード側の逆方向行の `position` は触らない（メンバーシップ不変の並び替えでは相手履歴も増やさない） |
| BE | **変更なし**（既存の replace + `ORDER BY position` を使う） |

## 目的と受け入れ条件

1. カード詳細で、紐付いた複数の PR URL を DnD または上下ボタンで並べ替えでき、再読込後も同じ順で表示される。
2. 同様に、関連アイテム（カード・URL）も並べ替えでき、再読込後も同じ順で表示される。
3. 並び替え失敗時は操作前の順に戻り、エラーメッセージが出る。成功していないのに成功扱いしない（L-001）。
4. 保存中は当該一覧の並び替え・追加・削除ができない。
5. タイトル／説明の autosave と並走しても、並び替え結果や他方の side フィールドを消さない（L-453、既存 `sideDirty`）。
6. カード切替・離脱中に完了した古い並び替え応答を新しいカードに載せない（L-037 / L-040）。
7. 関連の並び替えだけでは、相手カードの関連一覧の順序・履歴は変わらない。
8. 件数 0 または 1 のときは並び替え UI（ハンドル・上下ボタン）を **出さない**。

## 画面

詳細プロパティ欄の既存 PR 一覧・関連一覧を拡張する。

各行:

- 左（またはリンク左）に **ドラッグハンドル**（ボードのカードハンドルと同趣旨の `cdkDragHandle`。リンク操作と衝突させない）
- 中央: 既存どおりリンク表示
- 右: **上へ** / **下へ** ボタン、既存の削除ボタン
- 先頭行の「上へ」・末尾行の「下へ」は disabled
- 1件以下ではハンドル・上下を出さない（削除・追加は従来どおり）

リスト:

- `cdkDropList` を PR 用・関連用で **別リスト**（相互接続しない）
- `@for` の track: PR は URL 文字列、関連は既存どおり `kind + number/url`（インデックス track はやめる／使わない。L-035）
- フィールド注記を「登録順」から「並べ替え可」に合わせて短く更新する

アクセシビリティ:

- ハンドルに「並び替え（ドラッグまたは上下ボタン）」相当の `aria-label`（対象の短い識別子を含める）
- 上下ボタンにも同様のラベル（例: 「1つ上へ」）

見た目は既存の `.pr-list` / `.pr-item` を拡張し、新デザインシステムは導入しない。

## フロントの振る舞い

### 共通

- 並び替えは **純関数で次配列を計算**（例: index の swap / CDK `moveItemInArray` のコピー）→ 楽観的にカード state を更新 → 既存の `save(次配列)` 相当で PATCH。
- `save` 開始時に当該 side の dirty を立てる既存経路を維持（`applyPrSave` / related の apply）。失敗時は **並び替え直前に控えた配列**へ戻す。
- エラー表示は既存の詳細画面エラー経路（`onError` → 既存バナー／メッセージ）をそのまま使う。新しいエラー面は作らない。
- 進行中リクエストは既存の `cancel$` / `takeUntilDestroyed` でカード切替時に打ち切る。打ち切り後は **どちらのカードにも `apply` しない**（`next` が走らないこと）。
- 同一内容の再送はしない（ドロップで index が変わらない、端の上下など no-op は PATCH しない）。

### PR（`CardPrLinks`）

- `reorder(from, to)` または `move(index, delta)` を追加。`add` / `remove` と同じ `save(prUrls)` を使う。
- 検証・重複ルールは変更しない（順序だけ変える）。

### 関連（`CardRelatedItems`）

- 同様に `reorder` / `move`。送る JSON は現行の related 書き込み形（`kind` + `number`/`url` + `label`）。表示用 `title` は送ってもサーバ無視でよいが、既存 add/remove のペイロード組み立てに合わせる。
- メンバーシップが同じで順序だけ変わる PATCH では、サーバが相手行を増やしも減らしもしないこと（既存実装の前提）。本機能はそれに依存する。相手ラベルは触らない。

## API・永続化

変更なし。

- `PATCH /api/cards/{id}` に `prUrls: string[]` または `relatedItems: [...]` を送ると全置換。配列順が `position` になる（#36 / #28 済み）。
- 省略・他フィールド同時更新の意味は既存どおり。

## 履歴

- 並び替え成功で順が変わったときだけ、既存の差分検知で `prUrls` または `relatedItems` の履歴行が増える。
- インポート形式・履歴 UI のリンク化は変更しない。

## 対象外

- 専用 `/reorder` API、部分更新 API
- ボード／バックログ上での PR・関連の表示や並び替え
- PR と関連を一つのリストに統合すること
- 関連の相手側順序の同期、相手ラベル編集
- タッチ専用の別 UI、一括「順序を保存」ボタン

## 知見（実装時に見る）

- **L-001**: 失敗・キャンセルを成功扱いしない。失敗時は UI を戻す。
- **L-035**: 削除・上下は安定キー（URL / kind+id）または控えた配列上の index で次状態を組み、表示と操作のずれで別要素を動かさない。
- **L-037 / L-040**: 古い PATCH 応答を別カードに載せない。
- **L-038**: BE は既存 replace の1トランザクションに任せる（FE で中途半端な部分配列を送らない）。
- **L-039**: 成功時は応答の配列で state を揃える（既存 apply）。
- **L-453**: autosave flush と side 保存の並走で互いに消さない（既存 sideDirty）。
- **L-460**: フィルタ済み部分配列で保存しない（詳細は全件表示のまま）。
- **L-015**: 並び替え PATCH が title / description / 他方の side を消さない。

## テスト観点

- FE: PR 2件以上で DnD・上・下・端 disabled・1件以下で操作非表示、失敗時ロールバック、保存中 disabled、カード切替で古い応答を無視。
- FE: 関連も同様。カード関連・URL 混在リストの順序保持。
- FE: 並び替え中の autosave が `prUrls` / `relatedItems` を潰さない（既存 routing 系に近いケース）。
- BE: 新規テストは必須にしない（順序永続化は既存）。回帰で困る場合のみ最小の置換順テストを足す。
- 手動: 詳細で PR・関連を並べ替え → 再読込 → 履歴に順変更が出る。関連並び替え後に相手カードの順が変わっていないこと。
