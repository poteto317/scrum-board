# カード #153: アクセス欄をプロパティへ移す（設計）

## 目的

アイテム詳細で、タイトルと説明のエディタの間にあるアクセス欄（`fieldset.acl-fieldset`、凡例「アクセス」）を、右側の「プロパティ」の欄（`section.properties.properties-list`）の 1 項目へ移す。頻繁に触る項目ではないため、タイトルのすぐ下に説明が続くようにする。

## 変更

1. `frontend/src/app/item-detail.html`
   - `@if (canManage()) { <fieldset class="acl-fieldset"> … }` のブロックを、そのまま（属性・条件・中身を変えずに）切り取り、プロパティの欄の末尾、作成日時・更新日時（`div.timestamps`）の直前へ置く。関連（PR・アイテム）の後ろで、ステータスなどのよく使う項目より下になる。
   - 中身（閲覧・編集の選択、指定ユーザーのチェックリスト、「アクセス設定を保存」の `type="button"`、`role="alert"` のエラー、読み込み中の表示、`[disabled]` の条件）は変えない。
2. `frontend/src/app/item-detail.css`（`.acl-*` の規則だけを書き換える）
   - 欄の枠と余白を、ほかのプロパティ（`.assignee-field` など）に合わせる。枠線と内側の余白をやめ、`margin: 18px 0 8px`、凡例は「対応」の見出し（`.assignee-label`）と同じ `13px`・`font-weight: 550` にする。`fieldset` の既定の `min-width: min-content` で欄が広がらないよう `min-width: 0` にする。
   - 選択は `width: 100%`。`aside` は 264px 固定で、プロパティ欄の左の余白（18px）と選択の内側の余白・矢印を除くと、文字に使える幅は約 200px しかなく、16px の文字では最長の選択肢「全公開（ログイン不要で詳細可）」（15 文字、約 240px）が欠ける。そこで、2 列の表示（751px 以上）のときだけ、アクセス欄の選択を `font-size: 13px`（約 195px）と `padding-inline: 8px` にする。1 列の表示（750px 以下）では欄が画面の幅まで広がるため、iOS のフォーカス時のズームを避ける 16px のままにする。
   - チェックリストは、閲覧可・編集可を縦に並べ（今の `grid` のまま）、閲覧可・編集可の見出し（`span.acl-list-label`）の下で、ユーザーの行だけを `div.acl-user-list` で包み（HTML の変更はこの包みだけ）、そこに `max-height` と `overflow-y: auto` を付けて、見出しを残したまま、指定ユーザーが多いときは一覧の中でスクロールさせる。
   - 選択のラベル（`.acl-fieldset > label`）だけを `display: block` にし、ユーザーの行（`label.acl-user`）はグローバルの `label` の `display: flex` のまま並べる。各ユーザーの行は、チェックボックスを幅なり（グローバルの `input { width: 100% }` と `.properties input` の `width: 100%` を打ち消す）にし、名前は `overflow-wrap: anywhere` で折り返す。
   - `item-detail.css` のバイト数を、変更前（ビルドで 7.54 kB）より増やさない。宣言を足す分は、枠線・内側の余白など不要になる宣言を消して相殺する（`item-detail.css` は既に予算超過の警告が出ている。知見 L-792 のとおり、グローバルへ移して逃がすこともしない）。
3. `frontend/src/app/item-detail.spec.ts`
   - 管理できる人では、アクセス欄がプロパティの欄（`.properties-list`）の中にあり、タイトルと説明のエディタの間（`.detail-page-doc`）に無いことを固定する。
   - 管理できない人（`canManage: false`）では、アクセス欄が出ないことを固定する。
   - アクセス欄の中の Enter キー（プロパティ欄の中の選択を変えて keydown を送る）で、アクセスの下書きが変わり、自動保存（`updateItem`）が呼ばれないこと。保存中（`acl.saving`）に fieldset が無効になること、「アクセス設定を保存」が `type="button"` のままで、アクセス欄に `formControlName` を持つ要素が無いことを確かめる。

## フォームへの影響

アクセス欄は移動後も `<form [formGroup]>` の中（`aside` は同じフォームの子）にある。フォームは `(submit)="$event.preventDefault()"` で送信を止めており、フォームの中に `type="submit"` のボタンは無い（「アクセス設定を保存」は `type="button"`）。アクセス欄の `select`・チェックボックスは `formControlName` を持たないため、フォームの値と自動保存の対象にならない。移動前と同じ条件なので、Enter で意図しない送信や自動保存は起きない（知見 L-473: Enter と blur の二重確定を新たに作らない）。

## 狭い画面

750px 以下では `.detail-layout` が 1 列になり、`aside` は本文の下に回る。アクセス欄は幅 100% の選択と、折り返すユーザー名で構成するため、崩れない。この実行（非対話）ではブラウザを使えないため、狭い幅の見た目の確認は CSS の規則（幅 100%、`min-width: 0`、`overflow-wrap: anywhere`）で担保し、PR の本文に確認の観点を書く。

## 決めたこと

- 位置はプロパティの欄の末尾、作成日時・更新日時の直前とする（カードの推奨案「並びの後ろのほう」。ほかのプロパティは並べ替えない）。
- 見出しは今の `fieldset` と `legend`「アクセス」を使い続ける（まとまりの名前を保つ）。
- 選択の文字の大きさは、2 列の表示のときだけ 13px にする（文言は変えない）。
- スクロールの上限は、各一覧ごとに `12rem`（1 行は 13px の文字と行の余白で約 1.5rem のため、およそ 8 人分）とする。
- 凡例の文字の大きさと太さ、枠線と余白は、カードの要件 3（ほかのプロパティの項目に見た目を合わせる）に従って変える。
- 折りたたみや要約の表示は追加しない（範囲外）。`ItemAclPanel` とバックエンドは変えない。

## レビューの記録

サブエージェントによる設計書のレビューを 2 周行った。

## 確認した知見

- L-792（CSS 予算を逃がすためにクラスをグローバルへ移さない）: この設計はコンポーネントの CSS の中だけで書き換え、グローバルへは移さない。予算は `npx ng build` の `item-detail.css` の数値で判定する。
- L-473（Enter と blur の二重確定）: アクセス欄には文字の入力欄も blur での確定も無いため新たな二重確定は生まれない。その前提（`formControlName` が無い、ボタンが `type="button"`）をテストで固定する。
