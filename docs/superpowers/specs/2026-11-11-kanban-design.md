# スクラム学習用かんばん MVP 設計案

## 目的と制約
スクラムとAngular(TypeScript)・Goを学びながら機能を増やせるアプリ。データはMySQLへ永続化する。新規プロジェクトの配置案はプロジェクトルート。2026-11-11にユーザー承認済み。MySQLはDockerで起動する。

## アプローチ
1. 推奨案: Angular標準機能中心 + Goのnet/http・database/sql + MySQLドライバー。SQLとHTTPの仕組みを学びやすく、依存を少なく保てる。データアクセスとHTTP処理は分離する。
2. 代替案: Angular + GoのWebフレームワーク + ORM。CRUDの記述量は減るが、フレームワークとORM固有の学習が増える。
構成はユーザー承認済み。Angularは実装開始時に公式互換表と利用環境からサポート中の安定版を選び、依存をロックする。MySQLは8.4 LTS系を想定する。

## MVPの挙動
- 単一ボード。初期列はTodo、Doing、Done。任意名の列を末尾へ追加可能。空白名と同名列は拒否する。列の削除・改名・並べ替えは今回含めない。
- 列は固定幅で横並び。カードは各列に縦積み。列が画面幅を超えればボード内を横スクロール。カード数に業務上の上限を設けず、縦スクロールで閲覧する。MVPは一覧一括取得とし、大量データ向けページングは将来対応。
- カードはタイトル必須、説明は任意。追加先の列を選べる。新規カードはその列の末尾に表示する。
- カードを選択すると専用の詳細画面を開く。タイトル、説明、ステータスを編集して保存できる。ステータスの選択肢は現在の列。保存成功後にボードへ反映する。カード削除は確認を挟む。
- 保存中は重複送信を防ぎ、失敗時は入力を保持してエラーを表示する。取得中・空状態・再試行を表示する。
- ドラッグ＆ドロップと手動並べ替えは実装しない。Todoのサンプルカードとして「ドラッグ＆ドロップでカードの移動・並べ替えを実装する」を初期登録する。既存DBの起動時に繰り返し追加しない。
- ログイン、複数ボード、担当者、期限、スプリント、ストーリーポイント、リアルタイム共同編集は対象外。まずローカル学習用として扱う。

詳細画面: 戻る、タイトル、説明、ステータスの選択欄、保存、削除。日本語UI。スマートフォンでも列幅を維持して横スクロールする。

## 構成とデータ
frontend/ はAngularのstandalone構成、Router、HttpClient、Reactive Forms、Signalsを中心に利用。大規模な状態管理ライブラリは導入しない。
backend/ はGoのHTTP層、業務処理、データアクセスを分け、MySQLドライバーを利用。SQLはプレースホルダーを利用し、入力検証はサーバー側にも実装する。
columns: id、name、position、created_at。
cards: id、column_id(FK)、title、description、created_at、updated_at。
カード表示順は作成日時とidで安定させる。更新時は存在確認を行い、不正な列への移動は拒否する。同時編集はMVPでは最後の保存を採用。

## API
GET /api/board: 列とカードの取得。
POST /api/columns: 列追加。
POST /api/cards: カード作成。
GET /api/cards/{id}: 詳細取得。
PATCH /api/cards/{id}: タイトル・説明・columnIdの更新。
DELETE /api/cards/{id}: カード削除。
GET /api/health: 起動確認。
不正入力は400、未存在は404、重複列は409。内部エラーの詳細はクライアントへ漏らさない。

## 起動と学習
Docker ComposeでMySQL、API、フロントエンドを起動できるようにする。MySQLのデータは名前付きボリュームへ保存し、初期スキーマとサンプルを初回のみ適用。環境変数の例、ローカル開発手順、API概要、ディレクトリの役割、将来の拡張ポイントをREADMEへ記載する。

## 検証と受け入れ基準
フロントエンドのビルドとフォーム・ステータス変更の要所、Goの入力検証・API処理のテスト、MySQL接続でのCRUDと再起動後の永続化を確認する。ブラウザーで横スクロール、詳細からの移動、エラー表示を確認する。環境不足で実行できない検証は実行済みと区別して報告する。
ユーザーが列追加、カード作成、詳細編集、ステータス変更、カード削除を行え、再読込でも保存内容が維持されればMVPの完了。
