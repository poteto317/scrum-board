# 説明テキストへのリンク（アイテム #30）

## 背景

カード要件: (1) 表示名と URL を指定して説明文にリンクを追加できること（Slack／Notion 系）。(2) 既存のテキストを選択し、リンク追加で URL を付けられること。現状の説明はプレーンな `textarea` で、クリック可能なインラインリンクはない。関連 URL／PR リンクは別セクションであり、本文中の名前付きリンクとは別物（#29 の表示名 enrichment とは対象が違う）。

## 決めたこと

| 事項 | 採用 |
|------|------|
| 保存形式 | 説明文内の **Markdown リンク** `[表示名](url)`。スキーマ・API フィールド追加なし（1A） |
| 対象 | **description のみ**。タイトルは対象外（2A） |
| 編集 UI | **textarea 維持**＋ツールバー（リンク追加／選択→リンク）。保存値は Markdown のまま。autosave は既存どおり（3A） |
| クリック表示 | **詳細の説明のみ**。**フォーカス連動**: 非フォーカス時は描画ビュー、フォーカス（編集ボタンまたは描画領域クリックで編集開始）時は textarea。明示の「表示／編集」タブは作らない（4A） |
| URL 規則 | **https のみ**（関連の `isHttpUrl` より厳格）。長さ **2048**、改行・タブ等制御文字なし、`^https://`。`javascript:`・`data:`・相対・http は拒否（5A） |
| 表示名 | **必須**（trim 後空ならダイアログエラーで拒否・挿入しない）。表示名に `]` は不可 |
| Markdown 範囲 | **リンク構文のみ**。太字・見出し・HTML・画像などは解釈しない（プレーンテキストとしてエスケープ表示） |
| XSS／URL 手順 | (1) trim → (2) 長さ≤2048・改行なし・`https:` のみ許可判定 → (3) **同じ正規化文字列**を Markdown の `(url)` に書く → (4) 描画時も同じ許可判定を通し、合格した同一文字列だけを `href` に載せる → (5) 表示名はテキストエスケープのみ（URL を HTML エンティティ化してから `href` に載せるのではなく、属性バインディングで安全に渡す） |

## 目的と受け入れ条件

1. 説明に `[表示名](https://…)` を含められる。既存の `PATCH` description 自動保存で永続化する（新エンドポイント不要）。
2. 詳細の説明付近に **リンク追加** 操作がある。ダイアログで **表示名** と **URL** を入力し、確定で textarea のカーソル位置（または選択範囲）に Markdown を挿入／置換する。挿入後は既存 autosave が動く。
3. textarea 内でテキストを選択した状態でリンク追加すると、表示名の初期値が選択文字列になり、確定で選択範囲が `[選択文](url)` に置き換わる。
4. URL が https でない・空・2048 超過・改行あり・危険スキームのとき、または表示名が trim 後空／`]` を含むとき、確定しても挿入せずダイアログにエラーを出す（L-001）。
5. 非フォーカスの描画ビューで、有効な `[表示名](https://…)` がクリック可能なリンクになる（`target="_blank"`・`rel="noopener noreferrer"`）。リンクのクリックは **外部遷移のみ**（編集モードに入らない）。編集開始は「編集」ボタン、または描画ビューの **リンク以外** の領域クリック／明示操作とする。無効な括弧や非 https はリンク化せず、生テキスト（エスケープ済み）として見える。
6. リンク以外の文字（`<` や既存のプレーン説明）は HTML として解釈されず、そのまま読める。
7. description の文字数上限（10000）を超える挿入は既存バリデーションで拒否する。
8. ボード／バックログのカード文言は現状どおり（リンク描画なし）。関連・PR セクションの挙動は変えない。
9. 履歴の description 差分は従来どおり全文比較でよい（Markdown を特別扱いしない）。

## 永続化・API

- 変更なし。`description` 文字列に Markdown を含めるだけ。
- サーバーは description を従来どおり受け取り、Markdown の構文検証はしない（クライアントが挿入時に URL を検証）。既存行・既存テストを壊さない。

## クライアント挙動

### ツールバー

- 説明ラベル付近に「リンク」ボタン（文言は UI に合わせて短くてよい）。編集モード（textarea 表示中）でのみ有効。
- クリック時:
  - 選択あり → 表示名＝選択文字列、URL＝空のダイアログ。
  - 選択なし → 表示名・URL とも空のダイアログ（どちらも必須）。
- 確定: 表示名・URL とも検証 OK なら、textarea の `selectionStart`／`selectionEnd` で文字列を組み替え、form の description を更新して autosave をトリガー（既存の valueChanges／flush 経路）。`document.execCommand` は使わない。
- キャンセル: 何も変えない。

### 描画と編集切替

- **既定は描画ビュー**（非フォーカス）。description をセグメント化し、許可済みリンク区間だけ `<a>`、他はテキストノード相当。
- 編集開始: 「編集」コントロール、または描画ビューの非リンク領域への操作。textarea を出しフォーカスする。キャレット位置の厳密復元は必須としない（末尾可）。
- 編集終了: textarea の blur（ダイアログ表示中は除く）で描画ビューに戻る。未保存下書きは form 値として保持し、ライブ再取得の世代ガードは既存 autosave に従う。
- パーサは `[` 〜 `](` 〜 `)` の単純スキャン。ネストや複数行 URL は対象外。表示名に `]` は含めない。

### URL 検証（挿入時＝描画時と同一規則）

- 関連 URL の `isHttpUrl`（`related-item.ts`）と同等以上: trim 後、長さ ≤ **2048**、改行・タブ等の制御文字なし、**`^https://` で始まる**こと。
- そのうえで `new URL(s)` が成功し `protocol === 'https:'`。相対・http・javascript・data 等は不可。
- **許可判定が通った入力文字列そのもの**（`new URL` の `href` 再シリアライズ結果ではない）を Markdown の `(…)` に書き、描画の `href` にも同じ文字列を使う（L-018）。パーサが黙って落とす文字を残したまま合格させない。
- 失敗時はダイアログ内エラー。form は変更しない。

### 描画時の XSS 手順（固定）

1. テキストをリンク候補と非リンクに分割する。
2. 候補の URL 部分に上記許可判定を適用。不合格ならリンクにせず全文をテキストとして出す。
3. 合格時: 表示名はテキストとしてエスケープ（またはテキストノード）。`href` には許可済み URL 文字列のみ（属性バインディング）。`innerHTML` にユーザー生文字列を連結しない。

## 対象外

- タイトルへのリンク
- フル Markdown／WYSIWYG／contenteditable 置き換え
- ボード・バックログ上のリンク描画
- 関連 URL／PR セクションへの統合
- リンク編集用の専用 API・DB 列
- リンクのホバープレビュー、短縮表示名の自動取得（#29 とは別）
- 明示タブの表示／編集切替 UI

## 知見（実装時）

- L-001: リンク確定の成否を見てから textarea を更新。検証失敗で挿入しない。
- L-018: 挿入 URL ＝ 検証済み文字列 ＝ 描画 `href`（同一）。
- L-002: パース不能を「空の説明」にしない。原文を壊さない。
- セキュリティ: XSS。許可スキーム以外を `href` にしない。表示名をエスケープ。
- L-037 / L-040: 詳細のライブ再取得と説明編集中の世代ガードは既存 autosave に従う。**リンクダイアログ表示中も** Close 理由モーダルと同様に busy／再取得ガードに含め、カード切替時はダイアログを破棄する（確定時の selection が別本文へ刺さらないようにする）。
- UI: 描画↔textarea 切替で未保存下書きを落とさない。リンククリックは遷移のみ。

## 直せない／残す制約

- 表示名に `]` を含むリンクは Markdown 素朴パーサでは表現できない（初版は不可）。
- URL に `(` `)` を含むリンクは、`)` 終端パーサの切り詰め（L-018）を避けるため初版では拒否する。
- 既存説明に手書きで不正な `[x](javascript:…)` があってもサーバーは拒まない。描画時にリンク化しないことで緩和する。
