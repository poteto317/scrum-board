# カードリンクのワンクリックコピー

## 目的

Notion の右上にある「リンクをコピー」に近い体験で、カード詳細の公開 URL をワンクリックでクリップボードへ入れる。詳細画面とかんばんボード上のカードの両方から使えるようにする。

## 受け入れ条件

- 詳細画面に、リンクを表すアイコンのボタンがあり、押すとそのカード詳細の絶対 URL がクリップボードへ入る
- かんばんボードの各カードにも同様のアイコンボタンがあり、押しても詳細へ遷移せずコピーだけする
- 成功・失敗が利用者に伝わる（黙って失敗しない）
- コピーする URL は公開番号ベース（`/cards/{number}`）であり、内部 ID ではない

## 決めたこと

| 事項 | 採用 | 理由 |
| --- | --- | --- |
| コピー対象 | `location.origin + '/cards/' + number` の絶対 URL | 他アプリへ貼っても辿れる。公開番号を使う（L-035） |
| バックログ画面 | 対象外 | カード文面は「詳細画面」と「かんばんボードのカード」のみ |
| バックエンド | 変更なし | URL はフロントのルートから組み立てるだけ |
| クリップボード方式 | クリックハンドラで `navigator.clipboard.writeText`。API が無いときだけ一時 `<textarea>` + `document.execCommand('copy')`。`writeText` が reject したあとに fallback しない（await 後は user activation が消えるため）。copy イベント単体には依存しない（L-441 / L-442） | ユーザー操作直後の gesture 内で書く |
| ボード上の DOM | `.task-card` を `<a>` 単体から「コンテナ + 本文リンク + コピーボタン」へ変える | `<a>` 内に `<button>` を入れると不正 HTML になる |
| 詳細の配置 | 見出し行（`.detail-heading`）の右上にリンクアイコンボタン | Notion 右上のイメージ。PR URL 欄とは別物 |
| ボードの配置 | カード右上の既存装飾 `↗`（`.card-arrow`）を**置き換え**てコピーボタンにする | リンク操作だと分かるアイコンにし、クリックはリンク外の sibling なので遷移しない |
| フィードバック | 成功「リンクをコピーしました」／失敗「リンクをコピーできませんでした」を `aria-live="polite"` で出す。詳細は見出し付近に**可視**の短文、ボードは既存の並び替えと同様に live 領域（可視でも sr-only でも可だが、成否は必ず伝わること）。約 2 秒で消す。タイマーは破棄時に解除（L-108） | 成否を伝える（L-001）。失敗を黙殺しない（L-057） |
| アイコン | 可視はリンク風アイコン（インライン SVG または既存文字スタイルに合わせたシンプルなリンク記号）。ボタンに `aria-label="リンクをコピー"`。結果は live 領域で伝える（L-154 / L-156） | 「リンク」だと分かるようにする |
| ヘルパー配置 | `frontend/src/app/card-link.ts`（必要なら同名の `.spec.ts`） | 既存の `pr-url.ts` などと同階層 |
| PR リンク | 触らない | 別機能（GitHub PR の紐付け） |

## 方式

### 共有ヘルパー

フロントに小さな純粋関数を `frontend/src/app/card-link.ts` に置く。

- `cardDetailUrl(origin: string, number: number): string` — `/cards/{number}` を組み立てる。`number` は正の整数のみ想定
- `copyText(text: string): Promise<boolean>` — Clipboard API → 失敗時フォールバック。成功で `true`、両方失敗で `false`。例外を握りつぶして黙って成功扱いにしない（L-001）

コンポーネントは URL 組み立てとコピー結果の表示だけを持つ。

### 詳細画面

- カード読み込み成功時のみコピーボタンを出す
- クリックで現在カードの `number` から URL を作り `copyText` を呼ぶ
- 成功／失敗を live 領域へ出す。既存の保存ステータス用 live 領域と混ぜない（別の status 要素）

### かんばんボード

- 各カードを次の構造にする（クラス名は既存に寄せてよい）:

```html
<article class="task-card">
  <button type="button" class="copy-card-link" aria-label="リンクをコピー">…icon…</button>
  <a class="task-card-body" [routerLink]="['/cards', card.number]">…既存の本文…</a>
</article>
```

- カードのドラッグ＆ドロップ（`2026-11-14-card-drag-drop-design.md` §4.4）が入ったあとは、`<article>` が `cdkDrag` になり、本文リンクは `routerLink` ではなく `[attr.href]` + `(click)`（修飾キーはブラウザー既定、通常のクリックは `Router.navigate`）になる。コピーボタンとこの構造は変わらない
- 見た目は現状のカード相当を維持（ホバー、余白、影）。コピーボタンはカード内右上に重ねるか topline に置く
- ボード全体で 1 つの `aria-live` 領域を共有してよい（連打時は最新メッセージで上書き）
- `Board` コンポーネントに `copyCardLink(number)` を追加

### 対象外

- Web Share API、QR、短縮 URL
- バックログ一覧へのボタン追加
- カード URL スキーム変更（別カード #26）
- サーバー側の canonical URL やパーマリンク API

## エラーと権限

- `clipboard` が拒否された／非対応でフォールバックも失敗した場合: 「リンクをコピーできませんでした」を出し、成功扱いにしない
- カード未ロード時はボタンを出さない（詳細）
- コピー失敗でフォームやボードのデータを書き換えない

## 検証方針

- ユニット／コンポーネント: URL 組み立て（origin・number）、成功時メッセージ、失敗時メッセージ、ボードでボタン押下後にナビゲーションが走らないこと、詳細でボタンが表示されること
- Clipboard はモックし、成功／失敗の両方を固定する（L-059 の実クリップボードは手動または E2E 任意。必須の自動テストはモックでよい）
- 既存のボードカードリンク・詳細遷移のテストを構造変更に合わせて更新

## 知見の反映

- L-001: `copyText` の成否を呼び出し側が見て、成功メッセージと失敗メッセージを出し分ける
- L-057: クリップボード拒否・フォールバック失敗を黙って無視せず、失敗文言を出す（L-001 の失敗経路と同一 UI）
- L-035: 公開番号と内部 ID を混同しない
- L-108: フィードバック消去タイマーを破棄時に解除
- L-154 / L-156: アクセシブルネームを「リンクをコピー」に固定し、結果は live 領域
- L-441 / L-442: Clipboard API（＋フォールバック）を click から呼ぶ。空の copy イベント preventDefault はしない
