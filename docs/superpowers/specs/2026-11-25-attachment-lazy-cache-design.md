# 添付画像を遅延読み込みにし、キャッシュを長くする（#129）設計

## 背景

- 画面: 画像の `<img>` に `loading="lazy"`・`decoding="async"` が無く、コメントが多いと画面外の画像もすぐ読み込む。
- 配信（`GET /api/items/by-number/{number}/attachments/{id}/content`）: `Cache-Control: private, max-age=60` で ETag が無く、1 分後には全量を取り直す。取り直すたびに GCS へ 2 回問い合わせる（`Attrs` と `NewReader`）。種類は DB の `item_attachments.content_type` にあるので、`Attrs` は要らない。
- アップロード: GCS のライターが既定の 16 MiB のバッファを使う。添付は最大 5 MiB。

## 決めたこと

- **画面:** 添付画像の `<img>` に `loading="lazy"` と `decoding="async"` を付ける。幅と高さは、保存していないので指定しない（範囲外）。
- **配信のキャッシュ:** `Cache-Control: private, max-age=3600`（1 時間）と、強い ETag `"<添付 ID>-<バイト数>"` を付ける。添付の内容は、ID ごとに変わらない（ID は再利用されず、内容の差し替えも無い）。
  - **権限の確認は毎回行う。** 閲覧権限の確認（`commentParentItem`）は、これまでどおり、200 でも 304 でも先に通る。
  - `If-None-Match` が ETag と一致したら、本文なしで 304 を返す（`ETag` と `Cache-Control` は付ける。`Content-Type` は付けない）。その前に、添付が DB にあり、そのアイテムのものであることを確かめる。削除済み・別アイテムの添付は、これまでどおり 404 にする（304 にしない）。304 のとき、GCS には問い合わせない。
  - 200 と 304 に `Vary: Cookie` を付け、同じブラウザで別のセッション（別のユーザー、未ログイン）に切り替わったときに、前のキャッシュを使わないようにする。
  - `max-age` の間は、削除された添付のキャッシュが残りうるが、画像を指すマークアップも同時に消えるので、表示されない。権限を失った人が、すでにキャッシュした画像を 1 時間見られるのは許容する（`private` で、共有キャッシュには残らない）。
- **DB の読み取りは 200 で 2 回になる**（ETag のための行の確認と、本文を開くときの object_key の取得）。GCS への往復 1 回を減らす代わりに、速い DB の読み取りを 1 回増やす。304 は DB の 1 回だけで済む。また、304 は、ブロブの保管先が使えない状態でも返る（ブラウザはすでに本体を持っているので無害）。
- **GCS への問い合わせを 1 回に:** `Attrs` をやめ、`NewReader` が返す `Attrs.ContentType` を使う。種類は、DB の値（アップロード時に保存した許可済みの画像の種類。常にある）を優先し、GCS の値は保存された種類が空のときの予備とする。
- **アップロードのバッファ:** ライターの `ChunkSize` を 1 MiB（256 KiB の倍数）にする。
- 範囲外: 配信のタイムアウト処理で全量をメモリにためる件、メモリと同時実行の上限（セキュリティの #91・#99）、縮小版、幅と高さの指定。

## 受け入れ条件

1. 添付画像の `<img>` が `loading="lazy"` と `decoding="async"` を持つ。
2. 添付の配信に ETag と `max-age=3600` が付く。
3. `If-None-Match` が一致すると 304（本文なし、GCS を開かない）。不一致なら 200。
4. 削除済み・別アイテムの添付、権限の無い呼び出しは、`If-None-Match` があっても 404 / 401 / 403（304 にならない）。
5. GCS からの読み取りで、`Attrs` の呼び出しが無い（`NewReader` の 1 回だけ）。GCS のクライアントは単体テストで差し替えられないため、コードの確認で足りるとする。
6. アップロードの `ChunkSize` が 256 KiB の倍数で、既定（16 MiB）より小さい（定数をテストで確認）。
7. エラー応答（404 など）には、ETag と長いキャッシュの指定を付けない。

## 実装プラン

変更は添付の配信・保存・画面の数か所に収まるため、実装プランは作らず、設計書のサブエージェントレビューも省く（#125 と同じ扱い）。
