# 説明・ソリューション・コメントへの貼り付け（画像・リンク）と複数画像（#145）設計

## 背景

カード #145 は「アイテムの説明欄に画像を貼れるようにする。Notion のようにする。画像に限らず、対応できるものは全てしたい。PR を分けた方がよければ、Todo アイテムを項目ごとに起票する」。

画像の添付そのものは既にある（説明・ソリューションの「画像」ボタンとドラッグ&ドロップ、コメントの下書きの「画像」ボタンとドラッグ&ドロップ。本文には `![名前](/api/items/by-number/{n}/attachments/{id}/content)` が入る）。無いのは次の 3 つ。

- クリップボードからの貼り付け（Cmd+V / Ctrl+V）。スクリーンショットをそのまま貼れない。
- 複数の画像を一度に入れること（ボタン・ドロップとも先頭の 1 件だけを使っていた）。
- 選択した文字に URL を貼ってリンクにすること（リンクは「リンク」ボタンのダイアログだけ）。

## 決めたこと

- **範囲（ユーザーの選択）。** 今回の PR は「貼り付け一式」（画像の貼り付け、複数画像、選択への URL の貼り付けでリンク化）。残りの Notion 風の項目は、Todo カードを項目ごとに起票する（下の「起票した項目」）。
- **画像の貼り付け。** 説明・ソリューションのブロック、コメントの下書きで、クリップボードにファイルがあるときに、画像としてアップロードし、キャレットの位置に入れる。ただし、ファイルと一緒にプレーンテキストと HTML の両方が入っているとき（表計算・文書ソフトのセルのコピーなど）は、これまでどおりテキストを貼る。テキストがファイル名や画像の URL だけのとき（ファイルのコピー、ブラウザの「画像をコピー」）は、画像として扱う。
- **許可する画像は変えない。** JPEG / PNG / GIF / WebP、1 件 5 MiB まで（サーバーの検証と同じ）。許可されないファイルだけが貼られたときは、アップロードせずに案内を出す。
- **複数の画像。** 貼り付け・ドロップ・ファイル選択（`multiple`）のどれでも、許可された画像を先頭から 10 件まで、1 件ずつ順にアップロードする。成功するたびに本文へ入れ、次の画像はその直後に入れる。途中で失敗したら止め、入った画像は残し、「N 件中 M 件を追加」と伝える。サーバーが理由（1 アイテム 20 枚、プロジェクトの容量）を返していれば、その文言を出す。許可されないファイルや 11 件目以降は入れずに、終わった後で案内を出す。
- **選択への URL の貼り付け。** 文字を選択して `https://` の URL（1 つだけ）を貼ると、選択を `[選択した文字](URL)` に置き換える。URL と表示名の検証は、既存のリンクの挿入と同じ関数（`formatDescriptionLink`）を使う（L-018）。選択が無い、URL でない、選択に `]` や改行がある、選択そのものが URL（置き換えたい操作）、選択が既存のリンク・画像の記法に重なる、選択が `!` の直後から始まる、のどれかなら、通常の貼り付けのまま。選択の前後の空白はリンクの外に残す。上限（説明・ソリューション 10000 文字、コメント 4000 文字）を超えるなら、置き換えずにエラーを出す。説明・ソリューションのブロック、コメントの下書き、コメントの編集で使える。
- **アップロード中は本文を固定する。** 説明・ソリューションのブロックは、画像のアップロード・削除の間（`imageBusy`）だけ読み取り専用にし、Enter・Backspace による分割・結合、リンクの挿入、ブロックの追加も止める（挿入位置がずれて記法が壊れるのを防ぐ）。フォーカスは奪わない（別の欄へ移っていたら、戻さない）。アップロード中に次の画像が来たら、「アップロード中です」と伝える。コメントの下書きは、これまでどおりアップロード中は無効で、投稿の応答を待つ間はアップロードを始めない。
- **待っている間の切り替え。** アップロードの応答が返ったときに、別のアイテム・プロジェクトへ切り替わっていたら、または画面を離れていたら、その本文には入れず、残りの画像もアップロードしない。忙しい状態（ボタンの無効化）は必ず解く。コメントは、これまで切り替え後に忙しい状態が解けなかったので、あわせて直す。
- **判定は純粋な関数にする。** 添付画像の規則（種類・サイズ・件数の選別 `planImageUpload`）と文言は `attachment-image.ts`、貼り付けの判定（添付として扱うか `clipboardFilesToAttach`、リンクへの置き換え `pasteLinkOverSelection`）は `paste-content.ts`、1 件ずつ順に送る進め方（`uploadImagesInOrder`）は `upload-images-in-order.ts` に置き、説明のエディタとコメントで共有する。コンポーネントは、イベント、本文への挿入、API の呼び出しだけを持つ。
- サーバーと API は変えない。

## 受け入れ条件

1. 説明のブロックに画像を貼ると、アップロードされ、キャレットの位置に画像の記法が入る。
2. 複数の画像は、1 件ずつ順にアップロードされ、順番どおりに並ぶ。
3. 途中の失敗では、入った画像が残り、件数が伝わる。忙しい状態は解ける。
4. 許可されないファイルは入らず、案内が出る。許可された画像が 1 件も無ければ、何もアップロードしない。
5. アップロード中にアイテムが切り替わったら、切り替え先の本文には入らない。
6. 画像の添付が使えない場所（新規作成のフォームなど）と、無効のときは、貼り付けに手を出さない。
7. テキストと画像の両方があるクリップボードは、テキストとして貼られる。
8. 選択に `https://` の URL を貼ると、リンクになり、キャレットはリンクの直後に来る。選択なし・URL でない貼り付けは通常どおり。
9. 上限を超えるリンクは入らず、エラーが出る。
10. アップロード中は、ブロックの編集・分割・結合・リンクの挿入ができず、終わると戻る。2 回目の貼り付けは案内が出る。
11. 既存のリンク・画像の記法や URL を選択して URL を貼っても、記法は壊れない（通常の貼り付け）。
12. コメントの下書きでも 1〜5、7〜9 が成り立つ（貼り付けはキャレットの位置、ドロップとボタンは末尾）。コメントの編集では 8・9 だけが成り立つ。

## 範囲外

- コメントの編集中の画像の貼り付け（編集中は、これまでもドロップでアップロードしない。添付とコメントの結び付けの扱いを決める必要がある）。
- 貼り付けた後の「元に戻す」（Cmd+Z）。本文を書き換えるので、ブラウザの取り消しの履歴には入らない（「リンク」「画像」ボタンと同じ）。
- 画像の圧縮・変換（HEIC や TIFF、5 MiB を超える画像は、これまでどおり入らない）。
- コメントの画像の削除中にアイテムを切り替えると、忙しい状態が解けない（今回の差分の外の既存の動作）。
- 同じアイテムのコメントが再読み込みされた（AI チャットの反映など）ときに、アップロード中の画像が下書きに入らないこと（添付の一覧には残る）。
- アップロードが成功した後で本文に入らなかった画像（上限超過・切り替え）の削除。添付の一覧に残り、そこから消せる（これまでと同じ）。
