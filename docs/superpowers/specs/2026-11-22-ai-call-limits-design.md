# AI 呼び出し制限（課金防御）— 設計

- カード: [#58 AIチャット: 公開環境で課金が膨らまないように呼び出しを制限する](https://scrum-board-jkcejsb6ka-an.a.run.app/items/58?project=1)
- 親: #25 / MVP 方針: [#47](./2026-11-21-ai-chat-mvp-design.md)（#58 は共有セマフォ以外の課金防御）
- 関連済み: [#51 クレジット上限](./2026-11-21-ai-credits-limit-design.md) / [#54 設定 UI](./2026-11-21-ai-credits-settings-ui-design.md) / [#52 不可状態](./2026-11-21-ai-unavailable-states-design.md)
- 日付: 2026-11-22

## 背景

- 公開 Cloud Run（nginx Basic 内側）でも API 自体はセッション認証のみ。AI は呼び出しごとに Anthropic 課金が発生する。
- 既にある防御: 共有セマフォ最大 4（429 `ai_busy`）、ワークスペース・トークン上限（429 `ai_credit_limit`、未設定なら無制限）、メッセージ最大 4000 字、モデル文脈 20 往復、応答 maxTokens は chat **4096**／format **8192**。
- 運用上、Anthropic 側の自動追加課金を ON にしていないため、**制限機能は実装するが既定では有効にしない**（env 未設定＝レート制限オフ）。必要になったら env で有効化する。

## 決めたこと

| 項目 | 決定 |
| --- | --- |
| 本カードの主成果 | **核**: 利用者別レート制限（実装＋テスト）＋ Anthropic コンソール運用 docs ＋ クレジット超過の回帰。**付帯**: メッセージ長／文脈往復／chat maxTokens の env 上書き。実装プランでは核→付帯の Task 順 |
| 既定の有効化 | **オフ**。`AI_RATE_LIMIT_PER_MINUTE` 未設定または `0` で無効。長さ・maxTokens は現行ハードコード既定のまま（有効な env があるときだけ上書き） |
| env パース共通 | すべての新 env は **TrimSpace**（L-752）。空は未設定。不正値は **上書き未適用**（ハードコード既定を維持）＋起動時 slog 警告。黙って別の有効値に読み替えない（L-044）。Compose／シェルで意図せず export するとレートが有効になりうる点を docs に注意書き |
| レート単位 | **ログイン利用者ごと**（`CurrentUser` の user id）。AI は編集可＋セッション必須のままなので未ログイン経路は対象外 |
| 対象 API | `POST .../ai-chat` と `POST /api/items/refined`（クレジット拒否と同じ面） |
| 窓アルゴリズム | **スライディング 60 秒**: いまから遡って 60 秒以内の**許可回数**を数える。閾値 N のとき、許可回数が既に N なら次を拒否。壁時計の分境界は使わない |
| カウント対象 | **Try で原子予約**したリクエストのみ窓に残す。rate 拒否は予約しない。busy／列解決失敗は `Release` で外す（拒否連打でロック延長しない）。credit 拒否は Try 前 |
| 閾値（有効時の推奨値） | **20 回／60 秒／利用者**。env `AI_RATE_LIMIT_PER_MINUTE` が正の整数のときその値で有効。未設定・`0`・非整数・負は **無効**（起動時に slog で警告し制限オフ。黙って別数にフォールバックしない＝L-044） |
| 超過応答 | **429**、`code: "ai_rate_limit"`、メッセージ **「AIの利用頻度が高すぎます。少し待って再試行してください。」**。セマフォ取得・Anthropic 呼び出しの**前**、クレジットチェックの**後**に判定 |
| 実装形態 | プロセス内メモリ。単一 Cloud Run インスタンス想定。複数レプリカでの厳密共有は非目標 |
| メッセージ長 | 既定 **4000**。`AI_CHAT_MESSAGE_MAX` が整数かつ **≥1** なら上書き。未設定・不正は上書き未適用（既定維持＋警告） |
| 文脈往復 | 既定 **20**。`AI_CHAT_HISTORY_TURNS` が整数かつ **≥1** なら上書き。`0` は不正（上書き未適用）。未設定・不正は既定維持 |
| chat 応答 maxTokens | 既定 **4096**（`aichat` のみ）。`AI_CHAT_MAX_OUTPUT_TOKENS` が整数かつ **≥1** なら chat のみ上書き。format（8192）は本カードで触らない |
| クレジット原子予約 | **やらない**。#51 が「厳密抑止は #58 寄り」とした申し送りは、本カードではレート制限で暴走を抑える方針とし原子予約は閉じない（非目標のまま） |
| Anthropic コンソール | **docs のみ**（月額上限・自動チャージ OFF の確認手順）。アプリからコンソール API は呼ばない |
| FE | **必須変更なし**。既存 #52: サーバ `message` を出し draft 保持・成功扱いしない経路を壊さない（L-001）。`ai_rate_limit` 専用文言の追加は任意で AC 外 |
| OpenAPI | 429 応答の `code` 列挙に `ai_rate_limit` を追加。env 一覧は README または `docs/` 運用節 |

## 非目標

- 利用者別クレジット上限
- IP ベース制限、未ログイン公開 AI
- Redis 等でのレプリカ横断レート
- クレジット判定の原子的予約
- format（refined）の maxTokens env 化
- 設定 UI からのレート編集（admin UI は #54 のトークン上限のまま）
- 既定でレート制限を ON にすること
- FE の専用 UX（必須）

## 利用者体験

1. 既定デプロイでは挙動は現状どおり（レート制限なし。既存のセマフォ／クレジット／長さが効く）。
2. 運用者が `AI_RATE_LIMIT_PER_MINUTE=20` 等を設定すると、同一利用者の連打が 429 `ai_rate_limit` になる。
3. クレジット枯渇・混雑・レートはそれぞれ別 code で区別できる。

## サーバ変更概要

- レート制限ストア（userID → 予約時刻の列）を handler に注入。POST ai-chat／refined で credit チェック後・acquireSlot 前に `Try` で原子予約。busy や refined の列解決失敗など、モデル呼び出しに進まない場合は `Release`。
- wiring: env パース。無効時は no-op limiter。
- OpenAPI／docs: code・env・コンソール手順。

## 受け入れ条件（#58）

1. レート制限が **有効なとき**、閾値超過の ai-chat／refined が 429 `ai_rate_limit` と上記固定メッセージ（テスト）
2. レート制限が **無効（既定）のとき**、同条件でもレートでは拒否されない（テスト）
3. クレジット超過は引き続き 429 `ai_credit_limit`（回帰）
4. メッセージ長／history turns／chat maxTokens の env 上書きと不正値（上書き未適用）がテストまたは起動パース単体で確認できる
5. Anthropic コンソール月額上限の運用手順が docs にある
6. BE／OpenAPI が実装と一致する
