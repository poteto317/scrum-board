# スマホ用レイアウト（アイテム #46）

## 背景

カード要件: スマホ用のレイアウトを作る。かんばんボードでは各ステータスをセレクトボックスで選び、そのステータス（列）だけを表示する。初期は Todo。現状は狭い幅でも複数列の横スクロールのまま。

## 決めたこと

| 事項 | 採用 |
|------|------|
| 適用範囲 | **ボード＋バックログ**（詳細は既存の狭い幅対応のまま）（1B） |
| 切替 | **ビューポート幅**で自動（CSS `@media` ＋ JS `matchMedia` を同じ定数で同期）。広い画面は現行の複数列（2A） |
| セレクト | ボードツールバー内（フィルタ付近）。選択肢＝全列名（3A） |
| 選択の保持 | **ワークスペース設定に永続**（`board_settings`。既定は Todo 列）（4C） |
| 自由配置 | スマホ1列モードでは自由配置トグルを隠し、表示・DnD とも pack 相当（5A） |
| DnD | 表示中の1列内の並び替えは可。他ステータスへはセレクト切替後にドロップ、または詳細のステータス変更（6A） |

## 目的と受け入れ条件

1. ビューポート幅がボード用モバイル閾値（`max-width: 700px`）以下のとき、かんばんは **ステータス用 `<select>`** と **選択中の1列のみ** を表示する。他列の列コンテナは **DOM に出さない**（データバインドで選択列だけ描画）。非表示列への DnD ターゲットは存在しない。
2. 初回（未保存）および無効な保存値のとき、選択は **Todo 列**（列名 `Todo`。無ければ `position` 昇順・同点は `id` 昇順の先頭）にフォールバックする。
3. セレクト変更で表示列が切り替わり、選択は **サーバの board settings** に保存される（リロード・別端末で同じワークスペースなら復元）。保存失敗時は成功扱いしない（L-001）。表示は楽観更新してよいが、失敗時は前の選択に戻しエラーを出す。セレクト変更の楽観更新から PATCH 成否まで **`settingsSaving`（既存の layout 保存 busy と同等）を true** にし、その間はライブ poll が古い `mobileBoardColumnId` で選択を巻き戻さない（L-037 / L-040）。
4. 広い画面（701px 以上）では現行どおり複数列＋横スクロール。ステータスセレクトは **出さない**。
5. バックログは狭い幅で読みやすい1列リストを維持する。既存 `@media (max-width: 780px)` があるため、Task3 は **検証で残るはみ出し・ツールバー／フィルタの触れにくさを直す差分のみ**（不要なら CSS 変更ゼロ可）。ステータスセレクトはバックログには出さない。
6. スマホ1列モード（ボード・700px 以下）では「自由配置」トグルを出さない。**effective レイアウトは常に pack**: ソート・CDK ドロップ・`offsetY` スタイル・キーボード並べ替えは `settings.cardLayout === 'free'` でも pack 経路を使う（`isFreeLayout` 相当をモバイル中は false）。DB／応答の `cardLayout` 値自体は消さない（L-459）。広い画面に戻したら永続値どおり free/pack を再開する。
7. リストフィルタ・件数・既存のカード操作（開く、コピー等）はモバイルでも使える。
8. ライブ再取得中にセレクト操作中／設定 PATCH 中なら、古い GET で選択を巻き戻さない（受け入れ 3 の busy と同一）。

## ブレークポイント同期

- 定数は **1か所の TS 定数**（例: `BOARD_MOBILE_MAX_PX = 700`）と CSS の `@media (max-width: 700px)` を同じ値に保つ。
- **JS**: `matchMedia(\`(max-width: ${BOARD_MOBILE_MAX_PX}px)\`)` で `isBoardMobile` を更新（リスナー登録・破棄）。これが「1列だけ描画」「セレクト表示」「effective pack」「自由配置トグル非表示」の唯一の判定源。
- **CSS**: 同閾値で余白・見出し・**選択列の全幅表示**（現行の `.kanban-column { width/flex-basis: 248px }` 複数列横スクロール前提を、モバイル1列モードでは列がスクロール領域のほぼ全幅になるよう置換。横スクロールを前提にしない）。
- バックログ狭幅は現行どおり **`max-width: 780px`**（ボード閾値とは揃えない）。

## 永続化・API

- **読取**: `GET /api/board` の `settings` に含める（専用 `GET /api/board/settings` は無い）。
- **書込**: 既存の `PATCH /api/board/settings` を拡張する。
- DB `setting_key`: `mobile_board_column_id`（値は列 ID の十進文字列）。JSON キー: `mobileBoardColumnId`（number。存在する `columnId`）。
- `GET /api/board` の `settings` は常に `{ cardLayout, mobileBoardColumnId }` を返す。行が無い／無効 ID のときは **応答時点で Todo フォールバックした数値**を返す（DB 行は読取だけでは書き換えない）。列が1件も無いときは **`mobileBoardColumnId: 0`**（FE はセレクト無効）。シードは **`InitializeBoardSettings` のみ**（列が存在するまで挿入スキップ。Board GET 時は挿入しない。起動失敗にしない）。
- **部分 PATCH**: 現行の必須 `cardLayout` デコードは捨て、パッチ DTO はポインタ／Optional（`*cardLayout`, `*mobileBoardColumnId`）。**少なくとも一方必須**。省略したフィールドは変更しない（省略を pack 扱いしない）。`mobileBoardColumnId` のみの PATCH では `cardLayout` を変えない・`items` の position 再割当を起こさない。存在しない列 ID・0 以下は 400。未知トップレベルフィールドは 400。
- **PATCH 成功応答**: 常に両方の現在値 `{ "settings": { "cardLayout", "mobileBoardColumnId" } }` を返す（変更しなかったキーも落とさない）。`free`→`pack` のときだけ現行どおり `items` も付与。FE は応答 `settings` でマージ／置換しても欠落しないこと。
- DB 上の未知 `setting_key` は応答に載せず保持する（L-459）。
- 無効な保存値の修正タイミング: 読取時はフォールバック表示のみ。**ユーザーがセレクトで選んで PATCH 成功したとき**に DB を更新。読取のたびに自動 PATCH しない。
- マイグレーション: **新規テーブルは作らない**。既存 `board_settings` に `mobile_board_column_id` が無ければ、列が1件以上あるとき冪等 INSERT（Todo 列 ID。無ければ `position` 最小列）。

## クライアント挙動

- モバイル時（ボード・`isBoardMobile`）: ツールバーに `label`＋`select`（`aria-label`「表示するステータス」）。option は列の `name`、value は `columnId`。描画する列コンテナは選択中の1列のみ。空列は空状態メッセージ。列はボード幅に合わせて全幅。
- デスクトップ時: セレクト非表示、全列表示（現行）。effective レイアウトは永続 `cardLayout`。
- バックログ: Task3 は受け入れ 5 のとおり検証ベースの最小 CSS／マークアップ。DnD／フィルタ契約は壊さない。

## 実装プランの分割

1 つの実装プラン内で Task 分割: Task1 settings API／モデル（部分 PATCH・応答両キー・シード）、Task2 ボードの matchMedia＋セレクト＋1列 DOM＋effective pack、Task3 バックログ狭幅の残差分（検証後）、Task4 全体検証。

## 対象外

- 詳細画面のレイアウト刷新、ネイティブアプリ、PWA インストール
- スマホ専用の別ルート／別コンポーネントツリー全体の書き換え
- スワイプで列切替、ボトムナビ、プッシュ通知
- 自由配置のモバイル完全再現

## 知見（実装時）

- L-001: settings 保存の成否を見てから確定扱い。
- L-037 / L-040: ライブ再取得と編集中・保存中ガード（`settingsSaving`）。
- L-459: settings の未知キーを捨てない。自由配置フラグをモバイル表示のために永続値から消さない。

## 直せない／残す制約

- ブレークポイントはピクセル幅ベース（端末種別の厳密判定はしない）。
- ボード 700px とバックログ 780px は意図的に別閾値。
- 他列へのドラッグはセレクト切替または詳細経由（モバイル専用のマルチ列ドロップゾーンは作らない）。
