# アイテム期限（アイテム #18）

## 背景

カード要件: アイテムに期限を付けられること。期限は **日付＋時＋分** まで。入力は iPhone のタイマーのように **スクロールして選ぶ**。現状に期限フィールドは無い。

## 決めたこと

| 事項 | 採用 |
|------|------|
| 保存 | アイテムに **`dueAt`**。UTC の ISO8601（秒は常に `00`）。未設定は JSON **`null`**（1A） |
| 必須 | **任意**。クリア可（2A） |
| 入力 UI | 詳細に期限欄＋**年月日／時／分のスクロールピッカー**。確定で保存（autosave または専用確定。詳細はプランで固定）（3A） |
| 表示場所 | **詳細のみ**（ボード／バックログは初版対象外）（4A） |
| タイムゾーン | 入力・表示は **ブラウザのローカル**、保存は **UTC**（5A） |
| 履歴 | `dueAt` の設定・変更・クリアを履歴に残す（6A） |

## 目的と受け入れ条件

1. **すべての**アイテム JSON（ボード／単体 GET／PATCH 応答）に `dueAt: string | null` キーがある。未設定は必ず `null`（キー欠落なし。クライアント `normalizeItem` は欠落を `null` に補完）。
2. `PATCH /api/items/{id}` で `dueAt` を部分更新できる。
   - **省略**: 変更しない。
   - **`null`**: クリア（未設定にする）。
   - **`""`（空文字）**: **400**（クリアは `null` のみ）。
   - **文字列**: 受理形式は次のみ → (a) `Z` 付き UTC（例 `2026-11-17T08:30:00Z`）(b) 数値オフセット付き RFC3339（例 `2026-11-17T17:30:00+09:00`）。いずれも **UTC に正規化**し、秒・未満は `00` に揃えて保存・応答する。タイムゾーン無し（`2026-11-17T08:30:00`）・日付のみ・その他は **400**。暦として無効も 400。
3. 詳細に期限の表示と編集がある。スクロールで年・月・日・時・分を選び、確定で保存する。クリア操作で `null` を送れる。
4. 保存失敗時は成功扱いしない（L-001）。**確定前の表示値に戻し**、エラーを出す（下書きを成功扱いで残さない）。
5. 表示はローカル日時（例: `2026/11/17 17:30`）。保存・応答の文字列は常に `Z` 付き UTC（分まで、秒 `00`）。
6. ボード／バックログのカード面には期限を出さない（初版）。JSON には含める。
7. `dueAt` が変わったとき履歴に field `dueAt` が付く。before/after は API 応答と同型の UTC `…Z`（秒 00）、未設定は空文字 `""`。
8. ライブ再取得中に編集中なら、未保存の下書きを古い GET で上書きしない（L-037 / L-040）。**ピッカー表示中（未確定）**および **dueAt の side 保存中（`saving`）** も busy／世代ガード対象。**カード切替／destroy でピッカーを破棄**し、進行中の dueAt PATCH は `cancel$` で購読解除（related／assignee と同型）。
9. 既存 DB は起動時マイグレーションで `due_at` 列を追加し、既存行は `NULL`。

## 永続化・API

- DB: `items.due_at DATETIME NULL`（MySQL）。起動時 `InitializeDueAt` で不足時 `ADD COLUMN`。`001_schema.sql` にも追加。
- JSON: camelCase `dueAt`。応答は常に `null` または `…Z`（秒 00）。
- PATCH の省略と `null` クリアはポインタ／明示 null で区別する（L-002）。

## クライアント挙動

- モデル `Item.dueAt: string | null`。`normalizeItem` で欠落→`null`。side 適用・`applySideSave` でも **`null` を空文字にしない**（`?? ''` 禁止。L-002）。
- 詳細: 未設定時は「期限なし」＋設定ボタン。設定／編集でスクロールピッカー（年・月・日・時・分）。クリアで `null`。
- ピッカーの初期値: 既存 `dueAt` があればローカル換算、無ければ「今」の分を切り捨てたローカル日時。
- 年の範囲: 「現在年−1」〜「現在年＋5」（定数）。月日は暦に合わせる（31 日無い月は日をその月の末日へ丸める）。
- **DST**: ピッカーのローカル構成要素から `Date` を組み立て、無効な瞬間（春の飛び）はブラウザの `Date` 正規化結果を採用し、その Instant を `toISOString()` 相当で UTC `…Z`（秒 00）にして送る。応答の `dueAt` を同じ関数でローカル表示に戻し、**分単位で往復一致**することをテストで固定（L-018）。
- 保存経路: **専用 side 保存**（ピッカー確定／クリア時に `updateItem({ dueAt })`）。`sideFields` に `'dueAt'` を含め、**save 開始時に `markDueSideDirty`（または既存 `mark*SideDirty` と同型）** して form flush 応答で上書きされないようにする（L-453）。form の `fields` には載せない。

## 実装プランの分割

- **1 つの実装プラン**の中で Task を分ける（別 feature にはしない）: Task1 Backend（列・PATCH・履歴・docs）、Task2 FE モデル／side／normalize、Task3 スクロールピッカー UI、Task4 全体検証。

## 対象外

- ボード／バックログ上の期限表示・編集・期限切れハイライト
- 秒以下、タイムゾーン選択 UI、繰り返し期限
- 期限による自動列移動・通知
- ネイティブ `datetime-local` のみの UI（要件のスクロール選択に合わせる）

## 知見（実装時）

- L-001: 保存成否を見てから確定扱い。
- L-002: PATCH の省略と `null` クリアを区別。GET 欠落を空文字にしない（`null`）。
- L-018: 表示用ローカルと保存用 UTC を同じ瞬間に対応させる（往復で分がずれない）。
- L-037 / L-040: ライブ再取得と編集中ガード。
- L-453: form flush と side 保存の衝突を避ける設計にする。

## 直せない／残す制約

- 初版はボードに期限を出さない（カード要件のスコープを詳細入力に限定）。
- DST の「存在しない／重複する」ローカル時刻は、上記のブラウザ `Date` 正規化に従う（独自の壁時計表は持たない）。
