# コメント投稿者の偽装・横取り編集の防止（アイテム #96）

## 背景

コメント API は `author` をクライアント任意入力のまま保存し、カードの編集権限があれば誰のコメントでも PATCH/DELETE できていた（なりすまし・改ざん）。

## 決めたこと

| 事項 | 採用 |
|------|------|
| 投稿者 | セッション利用者からサーバが決定。表示名は `displayName`（空なら `loginName`）を trim し既存の 60 文字・制御文字規則へ正規化 |
| POST 本文 | `body` のみ受け付け。`author` キーは **400**（不明フィールド） |
| PATCH | `body` のみ。`author` 変更不可 |
| 作成者 ID | `created_by_user_id`（NULL 可・既存行はレガシー） |
| 編集・削除 | **本人**（`created_by_user_id` 一致）または **admin**。レガシー（ID NULL）は **admin のみ** |
| 一覧の author | 保存時スナップショットをそのまま返す（利用者の表示名変更後も過去コメントは変わらない） |
| API JSON | `createdByUserId`（number \| 省略可。レガシーは欠落または null） |

## 受け入れ条件（カード #96）

1. 他人の名前でコメントを投稿できない（`author` 送信は拒否、サーバが利用者名を設定）。
2. 他人のコメントを編集・削除できない（admin を除く）。テストで固定。

## 知見（手順 4）

- **L-085**: 未知キー拒否、権限はハンドラで所有者チェック。
- **L-974**: OpenAPI の requestBody / Comment スキーマを同期。

## レガシー

マイグレーション前に作られたコメントは `created_by_user_id = NULL`。表示は既存 `author` 列。改変は admin のみ。
